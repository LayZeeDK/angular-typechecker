```typescript
export interface CoreOptions {
  tsConfigPath: string | string[];   // single string OR non-empty array of ABSOLUTE leaf paths

```

From ../core/emit-advisory-notices:
```typescript
export function emitAdvisoryNotices(result: CoreResult, logger: Logger): void; // uses info/warn only; call BEFORE renderReport
```

From ../core/render-report:
```typescript
export interface RenderOptions { pathBase?: string; color: boolean; failFast?: boolean; }
export function renderReport(result: Pick<CoreResult,'diagnostics'>, options: RenderOptions): Promise<string>; // color:false strips ANSI
```

From ../core/evaluate-result (owns the 0-vs-1 verdict; a coverage-incomplete / warnings-exceeded run has errorCount===0 but success===false):
```typescript
export type Outcome = 'clean' | 'type-error' | 'coverage-incomplete' | 'warnings-exceeded';
export interface EvaluateOptions { maxWarnings?: number; strict?: boolean; }
export function evaluateResult(result, options?): { success: boolean; outcome: Outcome };
```

From ../core/exit-codes (VERDICT-BLIND by design -- pass it ONLY the caught error, never a completed result):
```typescript
export function toExitCode(input: Pick<CoreResult,'errorCount'> | TypecheckInfrastructureError): 0 | 1 | 2;
```

Executor compose order to mirror (executor.ts:44-81): normalize -> runTypecheck -> emitAdvisoryNotices(result, logger) -> renderReport(result,{pathBase,color,failFast}) -> evaluateResult(result,{maxWarnings,strict}); catch TypecheckInfrastructureError -> logger.error(...) -> return; re-throw anything else. The infra logger.error message string is locked verbatim: `angular-typechecker: the Angular compiler failed to run (infrastructure error, not a type error): ${error.message}`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| argv/env -> run() | Untrusted argv + env cross into run(); this is the CLI's only trust boundary. |
| resolved --tsConfig -> filesystem | A resolved tsconfig path is read by the core via ts/fs APIs (never a shell). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-02 | Denial of Service | main.ts realpathSync.native normalization | mitigate | Wrap realpathSync.native in try/catch (D-06 / Open Question 1); ENOENT on a nonexistent path falls through to the plain resolved absolute path so the core raises TypecheckInfrastructureError -> caught -> exit 2. run() never throws uncaught on a bad path. |
| T-26-03 | Tampering | main.ts --tsConfig path handling | mitigate | The core reads tsconfigs via ts/fs APIs only; run() performs NO exec/spawn of any user input -- keep it shell-free. node:path resolve/isAbsolute only. |
| T-26-04 | Information Disclosure | run() stdout/stderr routing | mitigate | stdout is EXCLUSIVELY the renderReport string (D-03); every notice/error routes through BufferingLogger to stderr; no advisory contaminates the byte-deterministic report stream. Asserted in main.spec.ts (notice-in-stderr / stdout-clean). |
| T-26-05 | Information Disclosure | diagnostic path output | accept | pathBase = process.cwd() (D-07) renders CWD-relative diagnostic paths rather than absolute -- matches the executor's CI-annotation intent. Low residual risk (local dev/CI tool). |
| T-26-06 | Information Disclosure | uncaught throw exposing a stack | accept | An unknown (non-infra) throw is re-thrown to bin.ts (Phase 27), which prints the stack to stderr -- acceptable for a dev tool; run() itself returns exit 2 for infra. |
| T-26-SC | Tampering | npm/pip/cargo installs | accept | ZERO new runtime/dev dependencies this plan (Node stdlib node:path/node:fs + in-repo pure core only). Nothing to audit. |
</threat_model>
