# Quick Task 260703-u74: Harden the scoped-name regression guard

## Goal

Resolve the guard-hardening findings deferred from PR #19/#20 review:
- **E1 (HIGH)** docs-only PRs skip the guard (the `test` job is code-gated).
- **E3** Nx per-project cache can stale-green the whole-repo scan.
- **E4/E5** the guard tests the scope-string symptom, not the executor-resolution invariant.
- **E8** the guard crashes (ENOENT) on a tracked-but-unstaged-deleted file (reproduced during #20).

## Tasks

1. **E1 + E3 (CI placement):** add a dedicated `scoped-name-guard` CI job that runs
   on EVERY PR (no `changes` gate) with `--skip-nx-cache`, and add it to the `ci`
   aggregate's `needs`. Runs the existing guard spec (single source), so docs-only
   PRs are covered and a warm per-project cache can't replay a stale green.
2. **E4/E5 (resolution invariant):** add a second guard to
   `scoped-name-guard.spec.ts` -- every executor id ending in a registered name
   (`:typecheck`) across all `project.json` + `nx.json` targetDefault keys must equal
   the canonical `angular-typechecker:typecheck` registered in `executors.json`.
   Catches aliased-scope / typo'd ids that resolve to the real executor (the disease).
3. **E8 (robust reads):** `findViolations` skips unreadable files instead of crashing.
