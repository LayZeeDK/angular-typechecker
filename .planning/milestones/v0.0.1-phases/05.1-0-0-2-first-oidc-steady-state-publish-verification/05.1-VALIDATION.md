### New regression assertions added this validation (durable, gap-closing)

Two genuine, durable invariants this phase introduced/proved were NOT previously asserted.
Both were added to the existing `release-hygiene.int.spec.ts` (no new framework, no new file)
and run green:

| Assertion                                                                                 | Why it is a real regression risk                                                                                                                                                                                   | Spec block                                                 |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| `setup-node` `registry-url: https://registry.npmjs.org/` is RETAINED                      | PKG-05's central empirical finding: registry-url is REQUIRED for npm to DETECT OIDC; dropping it (the now-superseded D-04 contingency) causes ENEEDAUTH on npm>=11.5.1 and silently breaks every tokenless publish | `PKG-04: the release workflow is supply-chain hardened`    |
| nx.json `release.git.push: false` AND `changelog.workspaceChangelog.createRelease: false` | Hard-won in 0.0.2: `createRelease` forces `git push` on, which would push an un-curated version commit + tag to force-push-protected main before curation; re-enabling either re-opens the force-push hazard       | `PKG-03: nx release is scoped to angular-typechecker only` |

Deliberately NOT added (avoiding busywork): a `package.json version == 0.0.2` assertion --
version is bumped every release, so a literal pin is not a durable invariant and would break
on 0.0.3. The live `version: 0.0.2` is proven by the Manual-Only `npm view` evidence instead.
