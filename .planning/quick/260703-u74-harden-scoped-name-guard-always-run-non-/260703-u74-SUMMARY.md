# Quick Task 260703-u74 - Summary

## What

Resolved the four guard-hardening findings deferred from the #19/#20 review.

## Changes

Commit 1 - `test(guard)`: `scoped-name-guard.spec.ts`
- **E4/E5** new "executor-id resolution invariant" guard: every executor id ending
  in a registered name (`:typecheck`) across all `project.json` + `nx.json`
  targetDefault keys must equal the canonical `angular-typechecker:typecheck`
  registered in `executors.json`. This tests the DISEASE (any aliased-scope or
  typo'd id that resolves to the real executor via a tsconfig path, exactly as the
  v0.1.0 bug did), not just the scope-string symptom the scan already covers.
- **E8** `findViolations` skips unreadable files (deleted-but-unstaged tracked
  files) instead of crashing on ENOENT.

Commit 2 - `ci`: `.github/workflows/ci.yml`
- **E1** dedicated `scoped-name-guard` job runs on EVERY PR (NOT `changes`-gated),
  so a docs-only PR can no longer ship a stray scoped ref in the README green.
- **E3** `--skip-nx-cache` forces the whole-repo scan to re-execute rather than
  replay a per-project `test` cache hit that a stray ref elsewhere never busts.
- Added to the `ci` aggregate's `needs`.

## Decisions

- **Single source, not a second scan.** The always-run job runs the existing guard
  spec (`nx test angular-typechecker --skip-nx-cache -- --run scoped-name-guard`)
  rather than re-encoding the scan in YAML/shell -- avoids the dual-encoding drift
  the reviewers warned about. It keeps running in the normal `test` job too (fast
  local/code-PR signal); the dedicated job is the always-run/non-cached backstop.
- **E5 invariant shape.** Keyed on "executor id ends in a registered executor name"
  (`:typecheck`) rather than trying to replicate Nx package resolution -- clearly
  correct for this workspace and catches scoped, aliased, and typo'd forms.
