# Plan: SARIF -> GitHub Code Scanning (dogfood angular-typechecker + fallow)

## Task 1 -- Add the `code-scanning` job to ci.yml

**Files:** `.github/workflows/ci.yml`

**Action:** Add ONE new job `code-scanning` (after the `scoped-name-guard` job, before
the `ci` aggregate). It must:

- `needs: changes`; `if: ${{ needs.changes.outputs.code != 'false' }}` (same NEGATIVE
  form as the heavy jobs so it stays in the `act -n` plan under the empty filter output).
- `runs-on: ubuntu-latest`.
- Job-level `permissions: { contents: read, security-events: write }`.
- `env: { NX_DAEMON: false, FALLOW_AUDIT_BASE: origin/main }`.
- Steps, all actions SHA-pinned (reuse the file's existing pins):
  1. `actions/checkout@9c091bb...` with `persist-credentials: false` and `fetch-depth: 0`
     (load-bearing for fallow's new-vs-inherited base attribution).
  2. `actions/setup-node@48b55a0...` node 24, `cache: npm`.
  3. `run: npm ci`.
  4. `run: npx nx build angular-typechecker` (so the CLI is runnable from dist).
  5. `run: node dist/packages/angular-typechecker/src/cli/bin.js -c apps/ng-spike-app/tsconfig.app.json --format sarif > angular-typechecker.sarif`
     with `continue-on-error: true` (a verdict-fail exit must not fail this reporting job;
     the redirect still writes the full SARIF before exit).
  6. `run: npx fallow audit --format sarif -o fallow.sarif --base origin/main`
     with `continue-on-error: true`.
  7. `name: Upload angular-typechecker SARIF` -- `uses: github/codeql-action/upload-sarif@b7351df727350dca84cb9d725d57dcf5bc82ba26 # v3.37.1`,
     `with: { sarif_file: angular-typechecker.sarif, category: angular-typechecker }`,
     `if: ${{ github.event_name != 'pull_request' || github.event.pull_request.head.repo.fork == false }}`.
  8. `name: Upload fallow SARIF` -- same action pin, `with: { sarif_file: fallow.sarif, category: fallow }`, same fork-gate `if:`.
- Add a header comment block matching the file's style (why-not-in-ci, least-privilege,
  fork-gate, path-gate, fetch-depth rationale).

**Do NOT** add `code-scanning` to the `ci` job's `needs` list. **Do NOT** touch the
existing `fallow` job or top-level `permissions`.

**Verify:**
- `./actionlint -color` passes (via the `lint-workflows` local run below).
- `bash tools/act/act-compat.sh` passes.
- YAML parses; the `ci` needs list is unchanged.

**Done:** ci.yml has the new job; `git diff` shows only an added job block (no edits to
existing jobs / top-level permissions).

## Task 2 -- Lock the new job's trigger fidelity in act-compat.sh

**Files:** `tools/act/act-compat.sh`

**Action:** Add, alongside the existing `assert_selected` lines:
- `assert_selected "$PR_PLAN" "ci/code-scanning" "pull_request"`
- `assert_selected "$PUSH_MAIN_PLAN" "ci/code-scanning" "push-main"`

**Verify:** `bash tools/act/act-compat.sh` -> `PASSED`.

**Done:** the new job is asserted present in both the PR and push-main act plans.

## Task 3 -- Local verification gates

**Action (no file changes):**
- Regenerate both SARIFs locally to reconfirm validity (built CLI on ng-spike-app;
  `fallow audit --format sarif -o`), assert `$schema` + `version 2.1.0` + driver names,
  then delete the throwaway `.sarif` files (never commit them).
- Run the CI workflow guards that read ci.yml: the `ci-e2e-coverage-guard` spec and
  `nx-surface-regression` spec (they must stay green -- the new job must not trip the
  e2e-coverage or surface guards).
- `actionlint` + `act-compat.sh` (Tasks 1-2).

**Done:** all local gates green; no stray `.sarif` files staged.

## Notes / constraints

- `main` is PR-only (empty-bypass ruleset): commit on the feature branch, open a PR,
  DO NOT merge (self-merge needs explicit user OK) and DO NOT approve any environment.
- The PR itself dogfoods: it changes `.github/**` + `tools/**` (code=true), so the new
  `code-scanning` job runs on the PR (same-repo branch, not a fork) and uploads both
  SARIFs -- verifying the wiring end-to-end in real CI.
