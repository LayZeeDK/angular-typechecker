# Quick Task 260703-lp0: Fix stray scoped `@angular-typechecker/angular-typechecker` references

## Problem

The v0.1.0 executor rename (`angular-typechecker:angular-typecheck` -> `angular-typechecker:typecheck`)
left a scoped double form `@angular-typechecker/angular-typechecker[:typecheck]` in the **dev
workspace, docs, and specs**. We do NOT own the `@angular-typechecker` npm scope; the ONLY sanctioned
`@angular-typechecker/*` name is `@angular-typechecker/source` (the Nx workspace-root package name in
root `package.json` / `package-lock.json`). The published package is `angular-typechecker` and its
executor is `angular-typechecker:typecheck`.

## Distributed package is UNAFFECTED (verified)

- Package name `angular-typechecker`; `files` ships compiled `src` (tsconfig.lib.json excludes all
  `*.spec.ts`/`*.drift.ts`), `executors.json`, `generators.json`, the package's own correct
  `README.md`, `LICENSE`.
- Shipped `init` generator writes only the unscoped id and guards against ever writing the scoped key.
- No `@angular-typechecker/angular-typechecker` in any shipped surface.
=> No v0.1.1, no tag, no npm publish. Land as a normal fix PR into `main` (main is PR-only).

## Root cause of silent-green CI ("how could specs pass with a wrong executor id")

Nx resolves a local plugin executor by requiring the package name with the workspace tsconfig
`paths` registered. The leftover alias `@angular-typechecker/angular-typechecker` ->
`packages/angular-typechecker/src/index.ts` makes the bogus scoped id resolve to the SAME executor
(proven: `npx nx run typecheck-consumer:typecheck` ran green, loading the real executor). No
node_modules symlink exists. The duplicate `nx.json` targetDefault gave the scoped-keyed target valid
cache config, and the two shape-only specs (`nx-target-defaults.spec.ts`, `target-defaults-drift.spec.ts`)
never assert the key maps to a canonical registered executor -- so the wrong id was an accidental
alias and no test caught it. The guardrail was inverted: two specs REQUIRED the wrong id.
