Scaffold the `angular-typechecker` plugin package and the real `apps/ng-spike-app` Angular 22
application, then perform the single most load-bearing edit in the phase: patch the plugin tsconfig
`module` from the generator default `commonjs` to `nodenext` so `await import()` survives `@nx/js:tsc`
emit (the GATE A enabling condition). Author the minimal Phase-1 plugin `package.json` (D-14).

default (`@nx/js` `library.ts:1132`, research-verified) -- leaving it unchanged makes GATE A fail by
construction (the built `.js` downlevels `await import()` to `require()` -> `ERR_REQUIRE_ESM`). The
`[BLOCKING]` module patch MUST land before any build or GATE-A assertion (Plan 03/04). The spike app
is the in-graph "real Angular 22 workspace" the gate's breadth check targets (D-07).

Output: the plugin skeleton (`@nx/js:tsc` build + `@nx/vitest:test`), the spike app, the patched
plugin tsconfig (`module: nodenext`), and the Phase-1 plugin `package.json`. This is the thinnest
viable slice the gate harness (Plan 04) runs against.
</objective>
