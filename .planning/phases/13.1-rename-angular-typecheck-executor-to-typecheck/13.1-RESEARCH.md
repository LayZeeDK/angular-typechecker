# Phase 13.1: Rename angular-typecheck executor to typecheck - Research

**Researched:** 2026-07-01
**Domain:** Nx plugin / executor identity rename (mechanical, behavior-preserving)
**Confidence:** HIGH (local-first; every claim verified against the live tree)

## Summary

This is a MECHANICAL, BEHAVIOR-PRESERVING rename of the single shipped Nx executor
`angular-typechecker:angular-typecheck` -> `angular-typechecker:typecheck`. There are no new
capabilities, no library additions, and no logic changes. The entire research reduces to four
things: (a) the COMPLETE, verified inventory of references that must change; (b) the
rename-safety discipline that avoids corrupting the package name `angular-typechecker` (of which
`angular-typecheck` is a prefix); (c) the Nx mechanics that make the rename safe (executors.json
key/paths, `git mv` of the impl dir, schema `$id`, nx.json targetDefaults keys); and (d) the
verification that proves the rename is complete and behavior unchanged.

I found and verified TWO distinct token families the planner MUST both handle. The CONTEXT
inventory covers family (1) but does not explicitly call out family (2):

1. **kebab-case executor short-name** `angular-typecheck` (as an id suffix, dir path, target
   key, run-command token, message prefix, and prose) -- **80 occurrences across 34 files**
   (outside `.planning/` + `CHANGELOG.md`). Isolated exactly by the PCRE lookahead
   `angular-typecheck(?!er)` (matches `angular-typecheck` NOT followed by `er`, so it never
   matches the package name `angular-typechecker`).
2. **Pascal/camel identity symbols** `AngularTypecheckExecutorOptions` (interface + schema
   `$id`, 19 occ) and `angularTypecheckExecutor` (default-export function + spec label, 2 occ)
   -- **21 occurrences, all confined to the executor directory** being `git mv`d. These are NOT
   caught by the kebab lookahead and are easy to miss; the negative grep gate needs a second
   pattern (`AngularTypecheck|angularTypecheck`).

**Primary recommendation:** Land this as a SINGLE atomic plan (no worktree parallelism -- an
intermediate split state breaks the build). Drive the edit from the two verified token
inventories below, use `git mv` for the directory, preserve every nx.json targetDefaults value
byte-for-byte while re-keying, then prove completeness with the dual negative grep gate
(`angular-typecheck(?!er)` == 0 AND `AngularTypecheck|angularTypecheck` == 0 outside
`.planning/`+`CHANGELOG.md`), the corruption canary (`typecheckr` == 0), and the existing test
suite + e2e (unchanged behavior, only ids/names/paths substituted).

## Nx Executor Rename Mechanics (confirmed local-first)

How Nx resolves this executor (verified against the live `executors.json` + `project.json` + a
passing e2e suite):

1. Consumer `project.json` target declares `"executor": "<package>:<key>"`.
2. Nx loads the package's `executors.json` (referenced by `package.json` `"executors"` field).
3. Nx looks up `executors[<key>]` -> `implementation` (an EXTENSIONLESS path, Nx appends `.js` and
   `require()`s it) + `schema` (path to the JSON schema).
4. The published id is `<package-name>:<key>` = `angular-typechecker:typecheck` after rename.

**Confirmed facts:**
- **Renaming the `executors.json` key** from `angular-typecheck` to `typecheck` changes the
  published id to `angular-typechecker:typecheck`. [VERIFIED: executors.json]
- **`git mv` of the impl dir is safe** because the build target's `assets` copy `executors.json`
  to the output root (`glob: "executors.json", output: "."`) and copy all non-`.ts` files from
  `src` preserving structure (`glob: "**/!(*.ts)"`), plus `**/*.d.ts`. `@nx/js:tsc` emits
  `executor.js` at the mirrored path. After the move + path update, the built
  `dist/packages/angular-typechecker/src/executors/typecheck/{executor.js,schema.json}` resolves
  correctly. [VERIFIED: packages/angular-typechecker/project.json build.assets]
- **The schema `$id` has NO runtime/tooling significance.** Nx locates the schema via the
  `schema` PATH in `executors.json`, never via `$id`. `$id` is a hand-authored JSON-Schema
  identifier. The existing `schema-parity.spec.ts` asserts `properties`/`required`/`version`/`cli`/
  `additionalProperties`/defaults -- it does NOT assert `$id` -- so renaming `$id` to
  `TypecheckExecutorOptions` breaks nothing and is pure hygiene (D-02). [VERIFIED: schema-parity.spec.ts + executors.json]
- **Two id FORMS both need re-keying (WHY they coexist):** the UNSCOPED published id
  `angular-typechecker:typecheck` is used where the package is installed as a real dependency
  (e2e consumer fixtures + their `nx.json` targetDefaults, which install the tarball); the SCOPED
  workspace id `@angular-typechecker/angular-typechecker:typecheck` is used by the dev-repo libs
  and one `nx.json` targetDefaults key (the local Nx project scope for the source plugin). Only the
  short-name segment changes in both. [VERIFIED: nx.json + libs/*/project.json + fixture nx.json]
- **The WALK-02 caching contract is a VALUE, the rename touches only the KEY.** Both nx.json
  targetDefaults blocks (`cache:true`, `outputs:[]`, the `default`-based inputs incl.
  `{projectRoot}/tsconfig*.json` + `^default` + `dependentTasksOutputFiles` + `externalDependencies`)
  are preserved byte-for-byte; only the object KEY string is re-keyed. [VERIFIED: nx.json lines 44-75]

## Common Pitfalls

### Pitfall 1: Prefix corruption (`angular-typechecker` -> `typecheckr`)
**What goes wrong:** A bare `angular-typecheck` -> `typecheck` replace mangles the package name.
**Why:** `angular-typecheck` is a strict prefix of `angular-typechecker`.
**How to avoid:** Anchor every edit on a Family-1 sub-class token (never the bare string). Gate
with `rg "typecheckr"` == 0 and package-name count non-decreasing.
**Warning signs:** `nx` cannot resolve the package; imports of `@angular-typechecker/...` fail;
lint `@nx/dependency-checks` errors.

### Pitfall 2: Missing the Pascal/camel family
**What goes wrong:** The kebab lookahead passes but `AngularTypecheckExecutorOptions` / `$id` /
`angularTypecheckExecutor` remain -- SC4 ("no stale reference") is violated in shipped source.
**Why:** `AngularTypecheck` (camelCase, no hyphen) is not matched by `angular-typecheck`.
**How to avoid:** Second gate `rg "AngularTypecheck|angularTypecheck"` == 0 outside `.planning/`.

### Pitfall 3: Single- vs double-quote target-key access
**What goes wrong:** A gate for the target key `"angular-typecheck"` (double-quoted) misses
`executors['angular-typecheck']` (single-quoted) in install-smoke/matrix/pnpm specs.
**How to avoid:** The `angular-typecheck(?!er)` lookahead catches BOTH quote styles -- use it as
the authoritative gate rather than quote-specific patterns.

### Pitfall 4: Message prefix (colon AFTER) vs id suffix (colon BEFORE)
**What goes wrong:** `angular-typecheck:` (message prefix in executor.ts/run-typecheck.ts) is a
different token from `:angular-typecheck` (id suffix). A `:angular-typecheck` gate misses the
prefixes.
**How to avoid:** The lookahead catches both. Decide the prefix target (D-05: `angular-typechecker:`)
and update any spec asserting the old prefix in lockstep.

### Pitfall 5: Stale dist / cache serving old paths
**What goes wrong:** `gate-a-static.spec.ts` (reads `dist/.../executors/<dir>/executor.js`) or
`tarball-audit.int.spec.ts` (asserts packed paths) fail or false-pass against a stale build.
**How to avoid:** Rebuild + `--skip-nx-cache` before the suite (see Runtime State Inventory).

### Pitfall 6 (observation, likely OUT OF SCOPE): README package-level `production` input
`packages/angular-typechecker/README.md` Option B (around line 105) still shows a `targetDefaults`
example using the `production` named input, whereas WALK-02 mandated `default` (the root README
recipe correctly uses `default`). This is a WALK-02 documentation nit, NOT an EXEC-01 rename target.
The rename must still change the `angular-typecheck` id in that block; whether to also fix
`production` -> `default` is a WALK-02 doc-correctness question -- flag to the reviewer, do not
silently expand scope.

  1. `npx nx build angular-typechecker --skip-nx-cache`
  2. `npx nx run-many -t typecheck-drift test -p angular-typechecker --skip-nx-cache`
  3. `npx nx run-many -t test -p angular-typechecker-install-e2e angular-typechecker-cache-e2e angular-typechecker-matrix-e2e --skip-nx-cache`

  from `.github/workflows/ci.yml`, so a local green predicts CI green.)
