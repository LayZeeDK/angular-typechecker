# Phase 13.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Behavior is UNCHANGED (pure identity rename); the strategy is (a) re-point every existing
> test to the new id/name/path and prove it still passes, and (b) add deterministic grep gates
> that prove completeness + non-corruption. Source: `13.1-RESEARCH.md` § Validation Architecture.

## Test Infrastructure

| Property | Value |

| **Full suite command** | see Sampling Rate (build + typecheck-drift + in-plugin test + 3 e2e + lint + format + grep gates) |
| **Estimated runtime** | ~minutes (e2e installs the tarball; in-plugin unit ~seconds) |

---

## Sampling Rate

- **After every task commit:** `npx nx test angular-typechecker --skip-nx-cache` + the SC4 grep gates.
- **After every plan wave / pre-commit (in order — mirrors `.github/workflows/ci.yml`):**
  1. `npx nx build angular-typechecker --skip-nx-cache`
  2. `npx nx run-many -t typecheck-drift test -p angular-typechecker --skip-nx-cache`
  3. `npx nx run-many -t test -p angular-typechecker-install-e2e angular-typechecker-cache-e2e angular-typechecker-matrix-e2e --skip-nx-cache`
  4. `npx nx run-many -t lint --skip-nx-cache`
  5. `npx nx format:check`
  6. Dual negative grep gate + corruption canary + package-name non-decreasing count.
- **Before `/gsd:verify-work`:** all of the above green.
- **Max feedback latency:** in-plugin quick run < ~60s; full e2e set longer (tarball install).
