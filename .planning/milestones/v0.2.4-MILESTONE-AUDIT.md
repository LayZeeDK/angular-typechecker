## Cross-Phase Integration (assessed inline)

The gsd-integration-checker spawn was substituted with an inline assessment because this milestone's cross-phase integration IS the SARIF -> Code Scanning pipeline, and that pipeline was proven END-TO-END in live GitHub CI (stronger evidence than a static agent read of workflow files):

- **RULE metadata (33) -> per-project categories (34):** every emitted diagnostic references a cataloged rule with family tags/severity/help; the per-project multi-run upload (distinct `automationDetails.id`, no `category` input) carries that metadata into one merged SARIF. Wired and drift-guarded; proven by the dogfood `code-scanning` job producing per-project analyses.
- **per-project categories (34) -> automated proof (35):** the `code-scanning-proof` job (PR-only, isolated fixture) asserts via the `gh` CLI that each expected alert lands with the expected category/tags/severity, red on any missing item (PROOF-01/02). Proven green in real CI (baseline run 29875173270) and the 35-04 file-less-upload fix.
- **automated proof (35) -> gating (36):** both Code Scanning jobs are required members of the `ci` aggregate; the dogfood job is un-path-gated so an analysis exists on every PR ref; the "Require code scanning results" ruleset requires `angular-typechecker` + CodeQL. Proven end-to-end: GREEN-on-clean run 29898624245 (`ci`+both jobs success), RED-on-regression chaos run 29901279596 (empty SARIF -> `code-scanning` failure -> `ci` failure), and the live ruleset clean on probe PRs #64 (planning-only, not deadlocked) and #65 (code).

No broken cross-phase wiring found. E2E flows: (1) real Angular diagnostics -> per-project SARIF -> Code Scanning alerts with correct rule metadata; (2) the merge gate reds on a missing/failed upload and greens on a clean PR without deadlocking planning-only PRs. Both PROVEN in production CI.
