# Quick Task 260715-050: Optimize e2e-tier CI wall-clock -- RESEARCH

**Researched:** 2026-07-15 (Windows arm64 dev box; branch gsd/v0.2.1-angular-cli-workspace-support)
**Domain:** GitHub Actions job-fan-out (matrix) vs cross-run cache; the `ci` aggregate contract; act/actionlint fidelity
**Confidence:** HIGH on the design + guard/gate/act impact (code-verified); MEDIUM on the wall-clock magnitude (no per-project CI durations yet -- the measurement plan closes this)

## Summary

Two levers were compared. **Lever A (split the single `e2e` job into a 4-cell matrix, one GitHub-hosted runner per e2e project)** is the DOMINANT lever, because the tier's wall-clock is CPU-bound-typecheck-dominated (nub/1gr both established that installs are a small fraction of each e2e project's runtime). A cross-run *cache* (Lever B) only shaves the network-fetch slice; **splitting parallelises the CPU-bound typecheck work itself across four machines** -- it attacks the actual bottleneck. **Lever B (the READY, code-reviewed `actions/cache` of `tmp/local-registry/storage` from 260714-nub)** is a cheap additive that becomes *more* valuable after a split: splitting destroys the in-job cross-project cache reuse that `clearStorage:false` gives today (install-e2e warms the proxy, ng-cli-e2e reuses it -- 1gr's flagship 93s->53s win), so each registry cell boots cold again unless a cross-run cache restores it.

**Recommendation: A+B, in that order, gated on one cheap measurement.** (1) First read the *current* tier's per-project vitest durations from one throwaway-PR run -- this is the go/no-go input for A. (2) If install-e2e is not ~the entire tier (expected: it is the largest but ~55-70%), apply A (matrix). (3) Then add B per-cell (it is authored + reviewed; near-zero incremental cost). Measure BEFORE vs A vs A+B on throwaway draft PRs; KEEP A if the matrix critical-path beats the current single-job e2e wall beyond CI noise.

**Single biggest risk:** the split's wall-clock floor is the **install-e2e cell** (37 tests, 11 spec files -- by far the heaviest project). If install-e2e alone is ~90% of the current serialized tier, the split saves almost nothing while costing a `GUARD-01b` rewrite (code review), ~4x replicated fixed-overhead runner-minutes (free on a public repo), and the loss of in-job cache sharing. Measure per-project durations FIRST; do not commit to A blind.

## (1) Lever A -- concrete split design

### Best split shape: a `strategy.matrix` over the 4 e2e projects (one runner each)

Weighed against the alternatives:

| Shape | Wall-clock | Verdict |
|-------|-----------|---------|
| **(i) matrix over 4 projects, one runner/cell** | `fixed + max(per-project)` = `fixed + install-e2e` | **CHOSEN.** Best wall-clock; public-repo minutes are free so 4 runners cost nothing extra in money |
| (ii) group `parallelism:false` pair vs parallelizable pair (2 jobs) | `fixed + max(install+cache serial, ng-cli+matrix)` | Worse than (i); no upside once minutes are free |
| (iii) shared BUILD job -> upload dist artifact -> cells download | adds a **serial ~100s build job in front** of every cell, and cells STILL pay `npm ci` (needed to run vitest+nx+publish); only saves the ~30s replicated build (free minutes) | **REJECTED.** Serialises a job ahead of the matrix -> net wall-clock LOSS; adds 2 more SHA-pinned actions + artifact plumbing for zero wall gain |

**Do NOT hand a dist artifact between jobs.** Each cell already rebuilds via each e2e project's own `e2e`-target `dependsOn: [{projects:[angular-typechecker],target:build}]` (the sl6 fix, GUARD-01e). The build (~30s incl. `test-util:build`) is dwarfed by `npm ci` + typecheck and runs *concurrently* per cell, so replicating it is free on a public repo and avoids a serial upfront job. Net: the recommended design introduces **no new GitHub Action** beyond the existing checkout/setup-node/pnpm-setup pins (+ the already-pinned `actions/cache` for Lever B).

### ci.yml sketch (drop-in replacement for the current `e2e:` job)

```yaml

    needs: changes
    if: ${{ needs.changes.outputs.code != 'false' }}
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        project:
          - angular-typechecker-install-e2e
          - angular-typechecker-ng-cli-e2e
          - angular-typechecker-cache-e2e
          - angular-typechecker-matrix-e2e
    env:
      NX_DAEMON: false
    steps:
      - uses: actions/checkout@9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0 # v7.0.0
        with:
          persist-credentials: false
      - uses: actions/setup-node@48b55a011bda9f5d6aeb4c2d9c7362e8dae4041e # v6.4.0
        with:
          node-version: 24
          cache: npm
      - run: corepack enable
      - uses: pnpm/action-setup@0ebf47130e4866e96fce0953f49152a61190b271 # v6.0.9
        with:
          version: 11.9.0
      - run: npm ci
      # --- Lever B (per-cell cache; add in the A+B step) ---
      - uses: actions/cache/restore@55cc8345863c7cc4c66a329aec7e433d2d1c52a9 # v6.1.0
        id: verdaccio-storage

            tmp/local-registry/storage

            !tmp/local-registry/storage/.htpasswd

            tmp/local-registry/storage

            !tmp/local-registry/storage/.htpasswd
```

**Load-bearing choice: `nx run-many -t e2e -p ${{ matrix.project }}` (NOT `nx e2e <project>`).** Both run the one project + its build `dependsOn`, but only the `run-many -t e2e`/`run-many -t typecheck` spelling preserves the substrings that `GUARD-01`/`GUARD-01c` regex-assert in the `e2e:` job block. Using `nx e2e <project>` would red those guards for no benefit. `[VERIFIED: ci-e2e-coverage-guard.spec.ts:165-176, 349-361 regexes `\brun-many\s+-t\s+e2e\b` / `\brun-many\s+-t\s+typecheck\b`]`

**Keep the job id exactly `e2e:`** -- `extractE2eJobLines` slices from `^  e2e:$` to the next job key; renaming the job throws a located guard error. `[VERIFIED: spec line 99 regex `/^ {2}e2e:\s*$/`]`

### The intra-job isolation constraints RELAX per cell -- but stay for the local full-tier run

The single-registry / `parallelism:false` / single-tarball constraints existed because 4 projects shared ONE runner (one `127.0.0.1:4873`, one `dist/`, one `tmp/`). On separate runners each cell owns its own registry, dist, and temp, so **cross-project contention cannot occur**:

- **Registry port.** Both registry-starting projects bind `127.0.0.1:4873` with `clearStorage:false` `[VERIFIED: both global-setup.ts:123-139]`. In one job they must never overlap (why install-e2e is `parallelism:false`). Split: install-e2e's `:4873` and ng-cli-e2e's `:4873` are on **different runners** -> no collision; the "yarn keys metadata cache by host, so a 2nd port breaks CI" hazard (the reason squ reverted a 2nd registry) is moot -- each cell has exactly one registry on one host.
- **`NX_INVOCATION_ROOT_PID` collision** (the n7z fix) only arose because two registry projects shared one root nx invocation. One registry project per cell -> it cannot arise. The `delete process.env.NX_INVOCATION_ROOT_PID` line stays (harmless).
- **`parallelism:false` on install-e2e / cache-e2e** becomes vestigial per cell (one project = nothing to serialise) but **must NOT be removed**: developers still run the whole tier locally with `nx run-many -t e2e --parallel=2`, where it remains load-bearing. GUARD-01b's `parallelism:false` + `--pack-destination` + no-in-spec-`nx build` assertions therefore stay valid (they protect the local full-tier path).

**What must still hold per cell:** (a) within the install-e2e cell, its multiple packing specs still share one dist dir, so per-spec `--pack-destination` isolation stays required; (b) no spec/setup rebuilds dist (build runs once via `dependsOn`); (c) the `e2e`-target build `dependsOn` (GUARD-01e) stays so the cell builds dist before its specs on a fresh runner. `[VERIFIED: GUARD-01b specs + project.json dependsOn]`

### Honest wall-clock tradeoff (grounded in this repo's numbers)

Recorded anchor: the **full e2e tier ran 10m20s (=620s) in real CI** (PR #35, sl6 SUMMARY -- includes ng-cli-e2e's first real-CI run). Model:

- **Per-runner fixed overhead** (paid by every cell, concurrently): checkout ~5s + setup-node(+npm cache) ~10s + `corepack enable` ~2s + pnpm-setup ~5s + `npm ci` ~40-60s + build (angular-typechecker + test-util) ~30s + typecheck-e2e ~15s ~= **~110-130s (~120s)**.
- **e2e work under `--parallel=2` today** ~= 620 - 120 ~= **~500s**, scheduled roughly as `install-e2e (alone) + cache-e2e (alone) + max(ng-cli-e2e, matrix-e2e)` because install-e2e and cache-e2e are `parallelism:false`.
- **Split wall-clock** ~= `fixed + max(per-project e2e time)` = `~120s + install-e2e_cell`. install-e2e is the heaviest project (37 tests / 11 spec files vs 4 / 7 / 9); the other three cells finish well under it, so **install-e2e is the floor**.

If install-e2e's own e2e work is ~300s, split wall ~= **~420s vs 620s -> ~200s / ~32% saved**; the concurrent replication of the ~120s fixed cost adds runner-*minutes* but not wall-clock, and public-repo minutes are free. **This 32% is a model, not a measurement** -- confirm with the per-project read in Section 5 before committing (Assumption A1). Lever B does not change this model's *shape* (it only trims the fetch slice inside install-e2e and ng-cli cells); it narrows the install-e2e floor slightly.

## (2) The `ci` aggregate gate + required-check contract -- NO change, NO ruleset edit

- **`ci` job `needs:` and gate are unchanged.** `needs.e2e` refers to the whole matrix job; with `fail-fast:false` the matrix job's rolled-up `result` is `failure` if ANY cell fails. The existing `contains(needs.*.result, 'failure') || contains(needs.*.result, 'cancelled')` gate already reads that rolled-up result, so a single cell failure fails `ci`. `[VERIFIED: ci.yml:364-386 -- the `contains(needs.*.result,...)` form was chosen precisely to aggregate matrix cells; same mechanism as the `test` matrix]`
- **No new required-check names.** Matrix cells surface in the Checks UI as `ci / e2e (install-e2e)` etc., but a status check is *required* only if the branch ruleset names it. The ruleset requires literally `ci` + the two CodeQL checks -- matrix cells are NOT separately required. **No ruleset edit is needed** (and the empty-bypass ruleset must not be touched, per AGENTS.md). A green `ci` (which needs the aggregated `e2e`) remains sufficient to merge.
- **Path-gating unchanged.** The matrix job keeps `needs: changes` + `if: ${{ needs.changes.outputs.code != 'false' }}`. The `if:` is evaluated once for the whole job -> all cells skip together on a planning-only PR -> `e2e` result `skipped` -> the gate (which dropped `skipped` from the fail set, D-08) stays green. The load-bearing negative `!= 'false'` form is preserved verbatim.

## (4) Interaction of A + B

- **Splitting REMOVES the in-job cache sharing that `clearStorage:false` provides today.** In the single job, install-e2e warms `tmp/local-registry/storage` and ng-cli-e2e (later in the same tier) reuses it -- 1gr's flagship win (ng-cli yarn `corepack yarn install` 93s->53s). On separate runners the ng-cli-e2e cell no longer sees install-e2e's warmed storage, so **it boots cold again**. Lever B (a cross-run `actions/cache`) is what restores per-cell warmth -- so **B is MORE valuable after A, not less.**
- **Per-cell cache scoping: add `${{ matrix.project }}` to the key** (shown in the Section 1 sketch). install-e2e's toolchain (Angular 22 + Nx 23 + TS 6 + Storybook) and ng-cli-e2e's (Angular CLI workspace) are different package sets; a per-cell key avoids two cells racing to save one key and keeps each restore tight. The broad `restore-keys` prefix (now also per-project) still yields a useful partial-warm hit; fidelity is safe by construction (`resetVerdaccioPublishState` wipes the plugin+htpasswd each run; `uplinks.npmjs.maxage:60m` revalidates -- the cache only changes speed). Only the **install-e2e and ng-cli-e2e** cells benefit (cache-e2e uses the source barrel -> no Verdaccio; matrix-e2e is npmjs-direct); the cache step is harmless on the other two (near-empty save), so applying it uniformly is simplest -- do not add per-cell `if:` gating.
- **Recommendation + order: A+B; A first.** A is the structural wall-clock lever (parallelises the CPU-bound typecheck bottleneck); B is the ready, reviewed, near-free additive that offsets the cache-sharing that A gives up. Measure A alone first (clean attribution), then stack B.

## (5) Measurement methodology + KEEP/REVERT

Mirror nub's throwaway-draft-PR approach: `main` is PR-only and feature-branch pushes fire nothing, so CI is triggered only by opening a PR; own-repo PRs are exempt from the AskUserQuestion upstream gate but are still outward-facing (the ~176-commit diff is cosmetic on a scratch base). Runs are ~20 min and orchestrator-driven; budget accordingly.

**Step 0 (go/no-go input for A -- do this on the CURRENT ci.yml):** open one throwaway draft PR on the unmodified tier and read the *per-project* durations from the `nx run-many -t e2e --parallel=2` step log (vitest prints each project's Duration), OR compute from the step wall-clock. This confirms whether install-e2e dominates. If install-e2e >= ~85% of the e2e work, **A is NO-GO** (split can't beat the install-e2e floor) -- do B only.

**Capture BEFORE (current single job):**
```bash
gh run list --workflow ci.yml --branch <head> --json databaseId,event,status,createdAt -L 10
gh run view <run-id> --repo LayZeeDK/angular-typechecker --json jobs -q '
  .jobs[] | select(.name=="e2e")
  | { name, seconds: ((.completedAt|fromdateiso8601)-(.startedAt|fromdateiso8601)) }'
```

**Capture AFTER (split matrix) -- critical path = earliest cell start to latest cell finish:**
```bash
gh run view <run-id> --repo LayZeeDK/angular-typechecker --json jobs -q '
  [ .jobs[] | select(.name | startswith("e2e (")) ]
  | { cells: [ .[] | { name, seconds: ((.completedAt|fromdateiso8601)-(.startedAt|fromdateiso8601)) } ],
      critical_path_seconds:
        ((( [ .[].completedAt ] | max ) | fromdateiso8601)
         - (( [ .[].startedAt  ] | min ) | fromdateiso8601)) }'
```

**Lever B miss->hit (within one PR -- a `pull_request` cache is scoped to the merge ref and restorable only by re-runs of the same PR):** run 1 = MISS (saves), then `gh run rerun <id>` = HIT; read the install-e2e and ng-cli-e2e cells' `run-many -t e2e` step durations MISS vs HIT.

**KEEP/REVERT criterion:**
- **A:** KEEP if the split critical-path is shorter than the current single-job e2e wall by a margin beyond CI noise -- pragmatic bar **> ~90s AND > ~15%**. Size noise with a second AFTER run (each burns ~20 min; no median-of-3). REVERT (restore the single `--parallel=2` job + revert the GUARD-01b edit) if within noise -- i.e. install-e2e is effectively the whole tier.
- **B:** KEEP if the HIT install-e2e/ng-cli step beats MISS by a clear double-digit-second margin exceeding hit-vs-hit spread (nub Section 4). Otherwise drop the two cache steps (one-hunk revert).

## (6) Pitfalls + gotchas (repo-specific)

1. **`GUARD-01b` `--parallel=2` assertion WILL red on a split -- rewrite it (product source change -> `/gsd-code-review`).** `ci-e2e-coverage-guard.spec.ts:241-255` asserts a non-comment `--parallel=2` line IS present and `--parallel=1` is NOT, inside the `e2e:` block. A matrix cell runs one project, so `--parallel=2` is gone. **Surgically replace only that `it(...)`** with an assertion that the ci.yml `e2e` matrix `project:` list EQUALS `enumerateE2eProjects()` (see pitfall 2). The other four GUARD-01b assertions (`--pack-destination`, install-e2e `parallelism:false`, cache-e2e `parallelism:false`, no in-spec `nx build`) stay valid -- they protect the LOCAL full-tier run. Editing this spec is a source change reviewed by the mandatory `code_review_gate`.
2. **The split TRADES `run-many`'s auto-coverage for an EXPLICIT matrix list -- guard it or a future e2e project is silently never run in CI.** Today `nx run-many -t e2e` (no `-p`) auto-covers any new e2e project (GUARD-01's guarantee). A static `matrix.project` list does not. The rewritten GUARD-01b assertion MUST parse the ci.yml matrix `project:` entries and assert they match the enumerated `e2e/*` projects (fail-loud on drift), preserving the anti-silent-miscoverage contract at the fast `test` tier. *Alternative (rejected for wall-clock):* a dynamic matrix (`nx show projects -t e2e --json` -> `fromJSON`) auto-covers new projects but adds a serial ~60-90s setup job ahead of the cells -- eroding the win; prefer static list + guard.
3. **`nx run-many -t e2e -p <one project>` vs `nx e2e <project>`.** Both run the single project + its build `dependsOn`; only `run-many -t e2e -p` / `run-many -t typecheck -p` keep the substrings GUARD-01/01c require. Do not "simplify" to `nx e2e <project>`.
4. **GUARD-01d is NOT affected** by dropping the `-p tag:type:e2e` selector -- it reads project.json tags only, never scans ci.yml. Per-cell `-p ${{ matrix.project }}` is fine.
5. **Keep the job id `e2e`** or `extractE2eJobLines` throws (all GUARD-01* ci.yml scans break).
6. **Registry cells share the `:4873` literal across runners -- fine** (different hosts). Do not reintroduce a 2nd registry port (yarn keys its metadata cache by host; squ reverted that).
7. **No new GitHub Action, no new SHA pin, no new permission scope.** The recommended design keeps checkout/setup-node/pnpm-setup (already pinned) and adds only the already-pinned `actions/cache@55cc8345863c7cc4c66a329aec7e433d2d1c52a9` (v6.1.0, verified latest). No `upload-artifact`/`download-artifact` (the artifact shape was rejected; for the record their current majors are v7.0.1 / v8.0.1 -- mismatched, another reason to avoid). `actions/cache` authenticates via `ACTIONS_CACHE_URL`/`ACTIONS_RUNTIME_TOKEN`, not the `permissions:` block -> the e2e job stays `contents: read`, tokenless-OIDC posture intact.
8. **Billing / concurrency.** Public repo = **free** GitHub-hosted minutes, so the ~4x replicated fixed overhead (extra runner-*minutes*) costs nothing; wall-clock is unaffected (concurrent). Peak concurrent jobs after split ~= 16 (6 test + 4 e2e + fallow + format-lint + act-compat + lint-workflows + scoped-name-guard + changes) < the 20-job free public-repo Linux concurrency limit. CodeQL runs in its own workflow.
9. **`changes`/paths-filter + matrix.** The single `if:` gates the whole matrix (all cells skip together) -- no per-cell filter surprises.
10. **corepack + pnpm-setup in every cell** is mildly redundant (cache-e2e needs neither; matrix-e2e needs pnpm; only ng-cli/install need yarn+pnpm). Leave uniform -- a few seconds, and per-cell `if:` gating is complexity for no wall gain.
