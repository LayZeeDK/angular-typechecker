<objective>
Add GUARD-01: a cheap, in-plugin self-audit test that asserts the CI `e2e` job's explicit `-p` project list equals the set of `e2e/*` projects in the workspace, so a forgotten or stale `-p` entry becomes a loud, LOCATED CI failure instead of a silently-skipped e2e project. Prove the guard actually fails on drift via a mandatory deliberate-RED probe.

Purpose: The `e2e` job runs its three e2e projects by an EXPLICIT `-p` list (`.github/workflows/ci.yml`), not `nx affected`. If someone adds a new e2e project and forgets to extend `-p`, that project is silently never run in CI — a type-checking tool that silently skips coverage is exactly the failure mode this milestone is closing. This guard codifies the current-correct coverage and goes RED only on drift.

Output: One new plain `*.spec.ts` under `packages/angular-typechecker/src/` (auto-routes into the existing 6-cell `test` matrix — no `ci.yml` structural change), plus a one-time deliberate-RED proof recorded in the phase SUMMARY.

EXECUTION NOTE (worktree posture): This is a cheap filesystem/text read with NO build/pack/install; it is worktree-safe. It is scheduled as the single plan in Wave 1 (runs on the main checkout as the cheapest/earliest signal, D-09) so that Wave 2's heavy tarball e2e (worktree-hostile, AGENTS.md D-22) is the sole plan in its own wave and runs on the main tree.
</objective>
