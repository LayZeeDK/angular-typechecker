### Getting a clean GREEN: build the workspace package the app imports

An Nx app leaf type-checks its app program, which transitively pulls a `.server.ts` page
importing `@analogjs/router/server/actions` -- a SUBPATH EXPORT that does not exist until the
`@analogjs/router` workspace package is BUILT. In the UNBUILT clone that import is an
unresolvable `TS2307` (analog's own state, not a tool defect), which is a legitimate exit-1
verdict. Building the package clears it:

analog's `@nx/...`/ng-packagr build for `router` emits **directly into**
`node_modules/@analogjs/router` (the build log's `to:` line), which is exactly where the
workspace `tsconfig.base.json` `paths` resolve `@analogjs/router` -- so after `nx build router`
the `/server/actions` entry point exists and the app leaf resolves cleanly. This is analog's
normal dev prerequisite (its own apps require the packages built), NOT an angular-typechecker
concern; the shipped bin simply reports whatever the compiler sees.

### Windows / MSYS note

On Git Bash use `/d/...` style paths, NOT `D:/...` -- Git Bash mis-parses the `D:` drive
letter as a remote host (this bites `cd` into the dist dir before `npm pack`). The
extensionless shim runs as `./node_modules/.bin/atc` from the clone root.
