## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test harness -> committed fixture file | The harness WRITES to a committed source file (the dep) to inject an error, then must reliably revert. |
| test harness -> shell (execSync) | The harness shells out to the real `nx` CLI. |
| consumer cache -> CI verdict | A lying cache (false PASS) would let broken code through CI -- the threat this whole plan exists to defeat. |

|-----------|----------|-----------|-------------|-----------------|
| T-04-08 | Tampering | harness leaves injected error committed | mitigate | D-15 crash-safe revert: committed `.pristine` sidecar + `beforeAll`/`afterEach` heal + `finally` byte-restore (preserve EOL) + a CI backstop `git diff --exit-code -- libs/typecheck-consumer-dep`. Mutate a non-`.spec` file the Vitest include glob ignores. NEVER `git checkout` (masks other edits, defeated by a killed worker). |
| T-04-09 | Repudiation / Tampering | a lying cache (false PASS) lets broken code through CI | mitigate | TEST-04 is the dedicated correctness gate (Pitfall 1): the green-then-broken transition asserts a CACHE MISS + the new diagnostic + non-zero exit after a dep error; the R1 `--check` pre-flight proves the dep source is hashed. Defense-in-depth, all three signals required (D-12). |
| T-04-10 | Tampering | command injection into execSync | mitigate | The harness builds the `nx` command from a FIXED target id + fixed flags + committed-constant fixture paths; NO untrusted option string reaches the shell. The injected error literal is built via `JSON.stringify` (no quote-escaping hazard). |
