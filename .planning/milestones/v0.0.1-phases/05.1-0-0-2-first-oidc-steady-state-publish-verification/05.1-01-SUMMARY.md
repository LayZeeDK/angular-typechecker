## Deviations and what they taught (the hard part)

This plan ran far from the happy path. Five distinct issues surfaced; all are now fixed AND
documented so they cannot recur:

1. **`createRelease:"github"` force-pushed an un-curated commit + tag before curation.** nx
   requires `git push` enabled when `createRelease` is set, so `nx release --skip-publish`
   pushed `6874f08` (un-curated 0.0.2) + tag to origin before the changelog was curated. Main
   is force-push-protected, so it could not be cleanly amended. FIX: `release.git.push:false`
   + `createRelease:false`; the maintainer now pushes the tag and creates the Release after
   curation (commit 38b7fbf).

2. **Reconciliation required a temporary ruleset disable.** The un-curated `6874f08`/tag could
   only be erased by force-push; the "v0.0.1" ruleset blocks force-push and the `gh` token
   lacks repo-admin to toggle it via API. The maintainer disabled the ruleset in the UI; main
   was force-pushed to the curated lineage and the tag moved to the curated `b5c84eb` (the
   "Release tag" ruleset's User bypass allowed the tag move); the ruleset was re-enabled.

3. **First OIDC publish 404'd, then ENEEDAUTH'd.** WRONG turn: per the ROADMAP/inline D-04
   contingency I dropped `registry-url` -> `ENEEDAUTH` (npm never attempted OIDC). RESTORED
   registry-url -> back to 404. **registry-url is REQUIRED for OIDC detection; D-04's "drop
   registry-url" advice is wrong for npm >= 11.5.1.**

4. **The actual root cause: the Trusted Publisher was never saved.** At 05-05 a simultaneous
   "Publishing access" change blocked the TP from being saved, so no OIDC identity existed to
   authorize -> the misleading 404. 0.0.1 used a token, so the TP was never exercised until
   now. Maintainer activated the TP -> the next publish succeeded immediately.

5. **`npm warn Unknown user config "always-auth"`** -- setup-node@v5 writes the deprecated
   `always-auth=true` into its generated `.npmrc`. Cosmetic, but fixed for future releases by
   a guarded `sed` strip step after setup-node (commit 6a21be0).
