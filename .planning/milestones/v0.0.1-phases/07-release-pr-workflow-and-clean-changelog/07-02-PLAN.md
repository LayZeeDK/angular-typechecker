<objective>
Add a path-aware skip to ci.yml so planning-only PRs neither burn the full cross-OS matrix NOR deadlock the required `ci` check (D-08, REL-02 DX). ~58% of this repo's commits are `.planning/`-only, so this is load-bearing for the Release-PR flow that routes everything through PRs.

The skip-aware aggregate gate (RESEARCH Runbook 3):

1. ADD a leading `changes` job that runs `dorny/paths-filter` to compute whether the PR diff touches anything OUTSIDE the planning/docs set.
2. GATE the heavy `test` and `e2e` jobs with `needs: changes` + the NEGATIVE `if: needs.changes.outputs.code != 'false'` (the negative form keeps them in the `act -n` plan when the filter output is empty under act -- Pitfall 3 / assumption A3).
3. REWORK the `ci` aggregate gate: add `changes` to `needs`; DROP `'skipped'` from the fail set (a path-skipped test/e2e is now acceptable); stay fail-closed on `failure` OR `cancelled`. The `ci` job id AND name stay exactly `ci`.

Leave `act-compat` and `lint-workflows` UNGATED (cheap; always validate the YAML). DO NOT add `paths-ignore` to the `on:` trigger (the deadlock anti-pattern -- a skipped workflow never reports the required check).

Purpose: full PR-mode protection (Plan 04) is only livable if planning-only PRs do not stall on a never-reporting or fail-closed `ci`. release.yml is FROZEN and untouched.
Output: a modified ci.yml with a `changes` job, two gated jobs, and a reworked `ci` gate; act-compat + actionlint still green.

This plan does NOT change live GitHub config (the ruleset switch is Plan 04, human-gated) and does NOT touch release.yml.
</objective>

## Trust Boundaries

| Boundary                       | Description                                                                                                                                                     |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| untrusted PR -> CI             | A PR (incl. forks) triggers ci.yml; the path filter + gate decide which jobs run. The gate must not let a real failure through nor deadlock a planning-only PR. |
| required-check name -> ruleset | The ruleset (Plan 04) requires the status check named `ci`; renaming or path-skipping the WORKFLOW would make the check never report and block merges.          |

## STRIDE Threat Register

| Threat ID | Category                 | Component                      | Disposition | Mitigation Plan                                                                                                                                                                                                                                |
| --------- | ------------------------ | ------------------------------ | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-07-04   | Tampering                | ci.yml `ci` aggregate gate     | mitigate    | Drop ONLY `'skipped'` from the fail set; keep `failure` AND `cancelled` fail-closed; the post-merge `main` `ci` run is the backstop. A genuinely mis-skipped job that GitHub reports as `cancelled` still fails.                               |
| T-07-05   | Denial of Service (self) | required `ci` check            | mitigate    | Never add `paths-ignore` to `on:` (a skipped workflow never reports -> merge button stuck "Expected"). Keep the workflow triggering on every PR; detect the diff INSIDE via `dorny/paths-filter`; `ci` runs `if: always()` and always reports. |

The SHA-pin discipline matches every other `uses:` in the repo.                               |
