# Phase 13.1 Learnings: rename-angular-typecheck-executor-to-typecheck

## Decisions

### Hard rename, no back-compat alias
The old id `angular-typechecker:angular-typecheck` was removed cleanly — no deprecated alias, duplicate `executors.json` key, or "renamed" error shim.

**Rationale:** The entire milestone is predicated on this being a genuine BREAKING change that drives `0.0.3 -> 0.1.0`; an alias would defeat the breaking intent and add machinery Nx has no first-class support for.
**Source:** 13.1-CONTEXT.md (D-01), 13.1-01-PLAN.md, 13.1-01-SUMMARY.md

### Full identity rename incl. git mv, schema $id, and the default-export function name
`git mv` the impl directory (history preserved), rename schema `$id` + the TS options interface to `TypecheckExecutorOptions`, and rename the default-export function `angularTypecheckExecutor -> typecheckExecutor`. The descriptive schema `title` (no `angular-typecheck` token) was kept.

**Rationale:** SC1 requires the directory + paths + `$id` renamed; SC4 requires no stale executor reference in shipped source. The default-export name has no Nx runtime coupling (Nx binds the default export, not the name) but renaming it keeps the SC4 gate clean (OQ1).
**Source:** 13.1-CONTEXT.md (D-02), 13.1-RESEARCH.md (Family 2), 13.1-01-SUMMARY.md

### Human-facing message prefixes moved to the stable package name
The diagnostic/log prefixes `angular-typecheck: ...` (3 in `executor.ts` + 1 in `run-typecheck.ts`) were changed to the package name `angular-typechecker: ...`, not to the new short-name `typecheck:`.

**Rationale:** The package name never renames and is unambiguous, so it is the right enduring human label; it also clears the last stale `angular-typecheck` tokens per SC4. Consequence: the package-name occurrence count rises 172 -> 176, so the completeness invariant is "non-decreasing," not "unchanged" (D-05).
**Source:** 13.1-CONTEXT.md (D-05), 13.1-01-SUMMARY.md

### Land the rename as ONE atomic commit
All 40 files (8 of them `git mv` renames) changed in a single breaking commit rather than per-task commits.

**Rationale:** An intermediate split state (some files renamed, others not) breaks both the build and Nx executor resolution, so the rename is indivisible.
**Source:** 13.1-01-PLAN.md (Task 4), 13.1-01-SUMMARY.md

### One-shot completeness gate, no standing guard test
The SC4 completeness check (dual grep gate + corruption canary + package-name count) was run as a one-shot verification step; NO permanent GUARD-01-style regression test was added.

**Rationale:** A behavior-preserving rename should not add standing test infrastructure; the one-shot gate is sufficient coverage and a standing guard was explicitly deferred (OQ3).
**Source:** 13.1-CONTEXT.md (OQ3), 13.1-VALIDATION.md

### Breaking commit only — no release cut this phase
The change landed as a single `feat(executor)!` with a `BREAKING CHANGE:` footer touching `packages/angular-typechecker/`; `nx release` was NOT run and no git tag was created.

**Rationale:** Per the repo's release mechanics, the 0.1.0 version cut happens later at the milestone Release PR, never mid-phase (D-06).
**Source:** 13.1-CONTEXT.md (D-06), AGENTS.md, 13.1-01-SUMMARY.md

## Lessons

### A rename inventory has two token families, not one
Beyond the kebab-case `angular-typecheck` surface (80 occ / 34 files, isolated by the PCRE lookahead `angular-typecheck(?!er)`), there is a second family of Pascal/camel identity symbols — `AngularTypecheckExecutorOptions` (interface + schema `$id`) and `angularTypecheckExecutor` (default export) — that the kebab pattern does NOT match. Missing it would leave SC4 ("no stale reference") violated in shipped source.

**Context:** Research caught this gap before planning; the completeness gate therefore needs TWO grep patterns (`angular-typecheck(?!er)` AND `AngularTypecheck|angularTypecheck`).
**Source:** 13.1-RESEARCH.md (Complete Rename Inventory, Pitfall 2)

### The TypeScript LSP feed is not authoritative — verify renames against the build + git grep
During execution the IDE `new-diagnostics` feed reported a stale `Cannot find name 'AngularTypecheckExecutorOptions'` at `normalize-options.ts:42` and `import.meta`/`.js`-extension errors in spec files — none of which existed in the committed tree (line 42 correctly used `TypecheckExecutorOptions`, and the 214-test suite passed).

**Context:** The load-bearing signals for a rename are `git grep`/`rg -P` over the committed tree and a fresh `nx build`/`nx test`, not the editor's tsserver snapshot (which lags edits and uses a different tsconfig lens). Confirmed by running the authoritative gates.
**Source:** 13.1-VERIFICATION.md (verification method), 13.1-RESEARCH.md (LSP false-positive note)

### The rename token is a prefix of the package name — anchor every edit
`angular-typecheck` is a strict prefix of the package name `angular-typechecker`, so a bare global replace corrupts the package to `typecheckr` and breaks everything. Every edit must be anchored on an executor-only token (`:angular-typecheck`, `executors/angular-typecheck`, the target-key strings, run-command tokens, the single-quoted `executors['angular-typecheck']` manifest access).

**Context:** The corruption canary (`typecheckr` == 0) + a non-decreasing package-name count deterministically catch a naive-sweep mistake.
**Source:** 13.1-CONTEXT.md (D-03), 13.1-RESEARCH.md (Pitfall 1)

### Nx resolves executors by the schema PATH, not the schema $id
Renaming the schema `$id` from `AngularTypecheckExecutorOptions` to `TypecheckExecutorOptions` has no resolver coupling — Nx locates the schema via the `schema` path in `executors.json`, and `schema-parity.spec.ts` never asserts `$id`.

**Context:** So the `$id` rename is pure hygiene (satisfies SC4) and cannot break resolution; the TS interface name must move in lockstep for compilation.
**Source:** 13.1-RESEARCH.md (Nx Executor Rename Mechanics)

### Stale dist/cache carry the OLD directory path — rebuild + skip-cache to verify
`gate-a-static.spec.ts` and `tarball-audit.int.spec.ts` read BUILT paths, and the Nx computation cache is keyed on the old executor id. A prior `dist/` still contains `src/executors/angular-typecheck/`.

**Context:** Verification must run after `nx reset` with `--skip-nx-cache` (and a fresh build) so a cached old-id PASS can never be trusted.
**Source:** 13.1-RESEARCH.md (Runtime State Inventory), 13.1-01-SUMMARY.md

## Patterns

### Single-atomic-commit rename
For an identity rename where resolution/build depends on all references agreeing, change every file in ONE commit rather than splitting across tasks/waves.

**When to use:** Any repo-wide rename of a resolved identifier (executor/plugin id, package export, target name) where a partial state is non-buildable.
**Source:** 13.1-01-SUMMARY.md (patterns-established)

### Dual-pattern grep gate + corruption canary + non-decreasing count
Prove a rename complete with: `rg -P "<kebab-pattern>(?!<suffix>)"` == 0 AND `rg "<CamelPattern>"` == 0, a corruption canary (the near-miss token) == 0, and a non-decreasing count of the token you must NOT touch.

**When to use:** Any rename where the old token is a prefix/substring of a token that must survive.
**Source:** 13.1-RESEARCH.md (Validation Architecture), 13.1-01-SUMMARY.md

### git mv first, then edit contents
Move directories/files with `git mv` before editing their contents so history is preserved atomically (`git log --follow` stays continuous), then do the token substitutions in place.

**When to use:** Any rename that moves tracked files, especially on Windows where tmp+mv idioms are unreliable.
**Source:** 13.1-01-SUMMARY.md, AGENTS.md / CLAUDE.md git rules

### Verify against fresh execution (nx reset + --skip-nx-cache)
Run every verification gate against fresh execution so a cached result under the OLD identity can never produce a false PASS.

**When to use:** Any change that alters cache keys (renamed targets/executors, changed inputs) before trusting a green suite.
**Source:** 13.1-01-SUMMARY.md, 13.1-VERIFICATION.md

### Re-pointed existing tests + one-shot gate = Nyquist coverage for a behavior-preserving change
For a rename/refactor with unchanged behavior, coverage is the EXISTING suite re-pointed to the new names (proven green) plus a one-shot completeness gate — not new standing tests.

**When to use:** Any behavior-preserving phase; avoids adding redundant test infrastructure while still proving completeness.
**Source:** 13.1-VALIDATION.md (Validation Audit)

## Surprises

### Package-name count went UP, not unchanged
The `angular-typechecker` count rose 172 -> 176 rather than staying constant, because the D-05 decision moved 4 human-facing message prefixes TO the package name.

**Impact:** The completeness invariant had to be defined as "non-decreasing (>= 172)" rather than "unchanged," or a correct rename would have tripped a strict-equality gate.
**Source:** 13.1-RESEARCH.md (package-name invariant note), 13.1-01-SUMMARY.md (grep-gate results)

### "Failed tasks" lines in a PASSING e2e run
The install/cache/matrix e2e run printed `Failed tasks: local-lib:typecheck-spec / app:typecheck` even though it reported "Successfully ran target test for 3 projects."

**Impact:** These are the deliberate injected-error sub-runs the e2e specs assert on (they expect a non-zero exit); mistaking them for real failures would wrongly block the phase. The orchestrating specs passed.
**Source:** 13.1-01-SUMMARY.md (Verification #3), 13.1-VERIFICATION.md

### git add aborted on a trailing pathspec naming the deleted old dir
An initial `git add` batch that listed the now-nonexistent `src/executors/angular-typecheck/` path aborted the whole batch; re-running without that path staged all 40 files (the `git mv` had already staged the deletions).

**Impact:** Minor, self-corrected — no rework — but a reminder that after a `git mv` the old path is gone and must not appear in a later explicit `git add` list.
**Source:** 13.1-01-SUMMARY.md (Deviations from Plan)
