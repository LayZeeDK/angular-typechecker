## What changed per task

### Task 1 -- test-util robustness (F1, L4) -- `test(test-util)` -- `a9cf2f7`

- **F1 (unsound purity needle removed at all sites):** Deleted the exported
  `ADVISORY_NOTICE_PREFIX = 'angular-typechecker:'` constant and its misleading head
  comment from `cli-e2e.ts`, its re-export from `index.ts`, and its import + the four
  `.not.toContain(...)` assertions across `cli-e2e.ts` (4) and the two e2e specs (2 +
  2). The needle collided on two axes -- ATC's own 90001/90002 synthesized diagnostic
  messages carry the same prefix (legitimate payload data) and the
  `angular-typechecker:typecheck` executor id contains it as a substring -- so a future
  not-found / empty-solution fixture under `--format json|sarif` would false-fail.
  Stdout purity now rests entirely on the whole-stream `JSON.parse` / `validateSarif`
  that was already present; a leading `> nx run` echo or trailing advisory text breaks
  the parse. Added a structural-purity note to the `assertMachineFormatParity` JSDoc.
- **L4 (lazy SARIF validator):** Wrapped the schema `readFileSync` + `new Ajv` +
  `addFormats` + `compile` in a memoized `getValidator()` (module-level
  `let compiled: ValidateFunction | undefined`), called from `validateSarif()`. Importing
  `@workspace/test-util` for any other helper no longer eagerly parses the ~109 KB
  schema. `validateSarif` signature and return shape unchanged; module-header comment
  updated to say the schema is compiled lazily on first call and memoized.

### Task 2 -- docs accuracy (F2, F3, F5) -- `docs` -- `fd20243`

- **F2 (byte-pure stdout scoped):** Rewrote the README post-`format`-example paragraph

  `> nx run ...` echo + trailing `NX  Successfully ran target ...` summary) with guidance
  to strip that framing or use the CLI / `ng run` for a byte-pure capture. Softened the

- **F5 (--fail-fast vs machine formats):** Added a sentence near the `--fail-fast` row
  stating it affects the human report only; `json` and `sarif` always carry every
  diagnostic. `--fail-fast` token kept in the options table.
- Tripwire constraints honored: no `non-goal` / `lands in a later release` in the README;

## Deviations from Plan

None functional. Two mechanical clarifications:

1. The plan's Task 1 done-criterion "`git grep` returns zero matches" is satisfied for
   all code sites; the only remaining matches are in historical
   `.planning/phases/32-verification-docs-additive-audit/*` artifacts (SUMMARY / LEARNINGS
   / VALIDATION), which are immutable records of what phase 32 built and out of scope to
   rewrite. Confirmed zero matches with `-- ':!.planning/'`.
2. `validateFormat`'s membership check uses `REPORT_FORMATS.some((format) => format === raw)`
   rather than `REPORT_FORMATS.includes(raw)`: `.includes` on a `readonly ReportFormat[]`
   rejects a `string` argument (TS2345), so `.some` compares against the typed list with
   no widening cast. Same semantics as the original inline `['human','json','sarif'].includes(raw)`.
