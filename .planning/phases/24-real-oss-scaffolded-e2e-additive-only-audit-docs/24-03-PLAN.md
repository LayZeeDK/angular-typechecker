## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| e2e publish step -> npm registry | The global-setup publishes the built tarball to a registry; it MUST be local Verdaccio (127.0.0.1), never the public registry |
| committed fixture -> repository | The fixture ships in git; it must contain no secrets/tokens and only first-party pinned Angular deps |
| tmp install (`ng add`) -> package resolution | Inherited `npm_config_*` (a leaked `legacy-peer-deps`) could mask a real on-stack peer result or retarget the install |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-05 | Tampering | e2e accidentally publishes to a real registry | mitigate | Copy the global-setup 127.0.0.1-only publish SAFETY gate VERBATIM (`if (!registryUrl.startsWith('http://127.0.0.1:')) throw`); re-assert the loopback invariant in the spec |
| T-24-06 | Information disclosure | committed fixture ships a secret/token or a peer-masking `.npmrc` | mitigate | Strip `node_modules`/`.git`; first-party pinned Angular deps only + committed `package-lock.json`; no fixture `.npmrc` with `legacy-peer-deps`; the Verdaccio `.npmrc` is written to tmp at test time, never committed |
| T-24-07 | Tampering | inherited npm config masks a real on-stack peer result | mitigate | `buildCleanEnv({ stripAllNpmConfig: true })` + `npm_config_userconfig` -> nonexistent path (Pitfall D); assert the on-stack install needs no flag |
| T-24-SC | Tampering | npm/pip/cargo installs | accept | No new package enters the SHIPPED plugin; the fixture declares canonical first-party Angular 22 devDeps only, verified against registry.npmjs.org (RESEARCH.md Package Legitimacy Audit -- none [ASSUMED]/[SUS]); Verdaccio proxies upstream at pinned versions |

No `high`+ severity threat exists in this plan's surface (test-infra + docs; the one network action is a loopback-gated publish, and no new shipped dependency). Stated explicitly per the security context.
