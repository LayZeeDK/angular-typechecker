# Quick 260720-13a: Address PR #47 review findings (guard + redaction) Summary

Two behavior-preserving root-cause fixes for confirmed PR #47 max code-review

## Task 1 (826eb85): guard `gatherLeafInto` against a Program-less infra crash

A surviving solution-walk / tsConfig-array leaf whose `performCompilation`
returned `{ program: undefined }` alongside a `500` threw a raw `TypeError` from
`gatherLeafInto`'s OBS-01 source-file deref (`result.program.getTsProgram()`)
BEFORE the caller could re-classify the already-unioned `500`. Added an
early-return guard on `result.program === undefined` placed AFTER the diagnostics
union push (so the `500` stays in `acc.rawDiagnostics`) and BEFORE the source-file
loop. The guard only `return`s (void) -- walk-references stays pure and free of the
run-typecheck import cycle, so the caller's post-walk `throwIfInfrastructureFailure`
(`handleSolutionWalk`) and post-loop `throwIfInfrastructureFailure`
(`handleMultiTsConfig`) classify the unioned `500` as a `TypecheckInfrastructureError`.
The crashed leaf contributes 0 authored files (`totalFilesCount` verdict-neutral).
Mirrors the direct path's guard shape in `run-typecheck.ts`.

Tests (RED then GREEN): extended the walk spec's `LeafSpec`/`stubCompilerCli` with
an additive `crashProgram?` flag (default keeps the valid empty-source Program, so
every existing test is byte-unchanged) + one solution-walk test asserting the walk
RESOLVES with the `500` in the union and `totalFilesCount === 0`; one
`infra-failure.spec.ts` test driving `runTypecheck` with an array `tsConfigPath`
asserting `.rejects.toBeInstanceOf(TypecheckInfrastructureError)`. Both failed RED
with `TypeError: Cannot read properties of undefined (reading 'getTsProgram')`
before the guard.

## Task 2 (1df16ba): `redactVolatile` replace-only-when-present

`redactVolatile` re-injected the `version` placeholder unconditionally, so a
reporter that dropped its tool version still matched the redacted JSON/SARIF
snapshots (the helper re-added `[version]`). Made redaction present-only on both
branches: the JSON top-level `version` and the SARIF `runs[].tool.driver.version`
now replace an existing key and NEVER inject one (mirroring the existing
missing-intermediate-level short-circuits). Behavior is identical when `version`
is present -- the real payloads always carry it, so the integration snapshots stay
byte-unchanged. Added `redact-volatile.spec.ts` covering present + absent cases on
both branches (2 present-cases passed RED, 2 absent-cases failed RED, all 4 GREEN
after the fix).
