**Seam observations (verified sound, no action):**
- The two pure detectors scan **opposite** targets deliberately: `detectTemplateCheckAborted` over
  the PRE-filter superset (a whole-program TCB abort must fire even for out-of-basePath poison);
  `detectBundlerQueryImports` over the POST-filter kept set (never name a boundary-dropped
  `?query`). A future refactor unifying them onto one arg would break SB-04/SB-09 -- currently
  correct.
- `notTypeCheckedDeclaredFiles` is aggregated only from **surviving** walk leaves (after every skip
  `continue`) and deduped, matching the direct path's single-leaf computation -- no double-count or
  leak from skipped leaves.

**One latent WARNING (out of v0.2.0 scope, tracked as tech debt):** `exit-codes.ts` `toExitCode`
mirrors only the `suppressedInGraphErrorCount>0` coverage-incomplete trigger, not the
warning-coverage / `templateCheckAborted` / zero-root-names ones. Intentional dead scaffold with no
live consumer (the Nx executor path is `evaluateResult -> {success}`), documented at
`exit-codes.ts:54-59`. Would only matter if a future standalone CLI wires `toExitCode`. Not
re-surfaced by the final integration check.
