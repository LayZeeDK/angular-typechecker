# Quick Task 260715-050: e2e CI wall-clock -- RESEARCH-2 (PR-vs-release differentiation + build-once)

**Researched:** 2026-07-15 (Windows arm64 dev box; branch gsd/v0.2.1-angular-cli-workspace-support)
**Domain:** GitHub Actions PR-vs-release track differentiation; build-once/test-many artifact handoff in an nx matrix; "test the exact published artifact"
**Confidence:** HIGH on the differentiation mechanisms + nx-flag facts + prior-art model (code/doc-verified); HIGH that the release-provenance gate already exists on the Release PR

## Summary

Two prior-art clones settle most of the open questions. **nx-verdaccio** (the reference publish-to-Verdaccio-then-install nx plugin) runs its e2e as an **OS matrix** with `nx affected -t nxv-e2e --skipNxCache`, publishing to Verdaccio *inside the target, per job* -- it does **NOT** hand a build/tarball artifact between jobs, and has **no PR-vs-release differentiation and no pre-publish e2e**. That directly validates this repo's per-cell-build approach (the `.nx/cache` handoff was already proven a no-op; nx-verdaccio doesn't even try it). **analog** reuses its build across jobs only because it has **Nx Cloud** (`NX_CLOUD_ACCESS_TOKEN`) -- a remote cache this repo deliberately lacks -- and its "test-what-you-shipped" check is a **separate `test-release.yml`** on **cron + `workflow_dispatch`** that installs the *published* package from real npm into fresh scaffolds. It is **post-publish, non-blocking, and lives outside the hardened release workflow.**

**Recommended two-track design.** **Track A (fast PR CI):** keep the per-project dynamic matrix (measured ~353s / ~43% faster), keep per-cell `dependsOn: build` + GUARD-01e (rebuild is ~2-4s), and **drop the no-op artifact upload/download** -- keep the discovery job only for the dynamic matrix. **Track B (release provenance):** the exact-artifact test **already runs** -- the `install-e2e` cell builds, publishes, and installs `dist/packages/angular-typechecker`, which *is* the exact packageRoot `release.yml` publishes, and it runs on the `release/x.y.z` -> `main` PR (a PR, so `ci` fires). No release.yml change needed. Optionally add a **separate** post-publish real-npm smoke workflow (analog's pattern) as an out-of-band safety net.

**Build-once mechanism for release e2e:** pack/publish-once is what `install-e2e` already does *within its job*; a cross-job tarball artifact is only worth it if paired with nx's real `--exclude-task-dependencies` flag (v19.6+, and this repo already uses it at `install-e2e/global-setup.ts:205`) -- but since the per-cell rebuild is ~2-4s, the artifact plumbing is net-negative for PR CI and unnecessary for release (the Release-PR cell already proves the artifact).

**Differentiation mechanism:** the release path is *already* differentiated by (1) `release.yml` being tag-triggered + hardened and (2) the Release PR carrying the version bump. A branch-gate (`if: startsWith(github.head_ref, 'release/')`) is available if you want regular PRs to skip the heavy provenance cells for more speed -- but that trades earlier feedback for a faster PR.

**Single biggest risk/tradeoff:** the dynamic `fromJSON` matrix breaking `act -n` / actionlint on an empty discovery output (`fromJSON('')`). Mitigate with `fromJSON(needs.<discover>.outputs.projects || '[]')` and validate locally with `bash tools/act/act-compat.sh` before any CI run.

## (2) Build-once-test-many in a GHA matrix -- the canonical pattern + the nx gotcha

**Canonical GHA pattern** ([CITED: actions/upload-artifact docs; oneuptime/lucavallin guides]): one build job runs `npm ci && build`, uploads the output via `actions/upload-artifact@v4` under a **single stable name**; matrix test jobs (`needs: build`) `actions/download-artifact@v4` the same name and test **without rebuilding**. In v4, upload names must be unique per producing job (append/overwrite is gone), and multi-artifact collection uses `pattern:` + `merge-multiple: true`.

**Why the canonical pattern does NOT apply cleanly to an nx repo here** (all three options assessed):

- **(a) Remove `dependsOn: build` + consume a `dist` artifact.** Reintroduces the fresh-runner ENOENT footgun the sl6 fix closed (a local `nx run-many -t e2e` would need a manual `nx build` first) and forces a GUARD-01e rewrite. **Rejected** unless paired with (c).
- **(b) Pack/publish the artifact once in the build job, cells install it.** Cleanest for "exact artifact" -- see (3). But note `install-e2e` **already** does build-once/publish-once/install-many *inside its own job*.
- **(c) An nx flag to run a target WITHOUT its `dependsOn`.** **`--exclude-task-dependencies` is real** -- introduced in **Nx v19.6** ([CITED: nx docs "Task Pipeline"; nrwl/nx#18053]) and **this repo already uses it** at `install-e2e/global-setup.ts:205` (`npx nx release publish ... --excludeTaskDependencies`). So `nx run-many -t e2e -p <project> --excludeTaskDependencies` would run the e2e target without rebuilding `angular-typechecker:build`. `--exclude-task-dependencies` is distinct from `run-many --exclude` (which excludes *projects*, not the dependsOn tree).

**Ranking (cleanliness + local-ergonomics):**
1. **Keep per-cell `dependsOn: build` (status quo).** The `.nx/cache` cross-runner handoff is rejected by nx (CRITICAL FINDING, verified on CI run 29393040360: `unknown-local-cache`), and a `dist`-only artifact is redundant because `dependsOn` rebuilds on a cold cache regardless. **The rebuild is ~2-4s** (tiny `@nx/js:tsc` lib) -- cheaper than the artifact plumbing (+2 SHA-pinned actions, +serial build wait). Preserves local `nx run-many -t e2e` ergonomics + GUARD-01e untouched.
2. **Artifact + `--exclude-task-dependencies`** only if a future build genuinely dominates (it does not today).
3. **Remove `dependsOn`** -- worst; breaks local flow and GUARD-01e for a ~2-4s theoretical gain.

## (3) Pack-the-tarball-once -> all e2e cells install the same `.tgz`

**Feasibility for this repo:** `install-e2e`'s `global-setup.ts` already implements the strong form of build-once *within its job*: it builds `dist/packages/angular-typechecker` (once, via `dependsOn: build`), publishes it to a local Verdaccio (`nx release publish --first-release --excludeTaskDependencies`, provenance stripped), and every spec installs from that one registry. Extending this **across cells** (a build job packs one `.tgz`, uploads it, cells download + install it) would require:
- specs that currently pack inline (`npm pack --json --pack-destination`, guarded by GUARD-01b) to instead read a pre-packed tarball path from an env var (e.g. `E2E_TARBALL`);
- `global-setup.ts` to publish the *downloaded* tarball rather than re-publishing a locally-built dist.

**Is this how nx-plugin repos do it? No.** nx-verdaccio -- which *exists* to publish-to-Verdaccio-then-install -- does **not** pack-once-and-upload. Each e2e matrix job runs `nx affected -t nxv-e2e --skipNxCache --verbose`; the Verdaccio publish happens *inside* the `nxv-e2e` target, per job, cache-skipped ([file: `nx-verdaccio/.github/workflows/ci.yml:75-97`]). So even the canonical plugin **rebuilds + republishes per job** -- confirming per-cell build is the ecosystem norm, not an anti-pattern.

**Verdict:** for **PR CI**, pack-once-across-cells is not worth it (per-cell build ~2-4s; adds artifact plumbing + spec rewrites). For **release provenance**, the tightest "exact bytes" proof is a pack-once-in-build-job -> upload -> cells-install-that-`.tgz` design -- **but** the Release-PR `install-e2e` cell already publishes+installs the exact `dist/packages/angular-typechecker` release.yml ships, so this extra plumbing buys only marginal tightness. Keep it as a *possible* future hardening, not a now-task.

## (4) How nx itself + nx-plugin repos structure e2e in CI

- **nx-verdaccio** ([file: `.github/workflows/ci.yml`]): triggers `push: [main]` + `pull_request: [main]`. Jobs `unit-test`, `int-test`, `e2e` each an **OS matrix** (ubuntu/macos[/windows]). e2e = `nx affected -t nxv-e2e --exclude="tag:type:example" --skipNxCache --verbose`. Verdaccio publish-then-install lives inside the target. **No build-once artifact, no PR-vs-release split, no pre-publish e2e.** Uses `nrwl/nx-set-shas` for `affected`.
- **analog** ([files: `.github/workflows/ci.yml`, `release.yml`, `test-release.yml`]): ci.yml `e2e` job has `needs: build` -- but that is a **fail-fast gate**, not an artifact handoff; the build output is reused across jobs via **Nx Cloud remote cache** (`NX_CLOUD_ACCESS_TOKEN`), which this repo does **not** have. Release = `semantic-release` on `push: [main, beta, alpha]` with `contents: write` + `id-token: write`, **no pre-publish e2e**. The "test-what-you-shipped" check is a **separate `test-release.yml`** on `schedule` (cron) + `workflow_dispatch` that installs the *published* package from real npm into fresh scaffolds (`npm create analog@latest`, `create-nx-workspace --preset @analogjs/platform@latest`, `@angular/cli new` + `npm install @analogjs/platform@latest`). **Post-publish, non-blocking, outside the publish workflow.**

**Takeaway:** neither repo runs a pre-publish e2e gate inside the publish workflow; neither hands a build/tarball artifact between jobs without a remote cache. The "test the shipped artifact" concern is handled either *in-band per e2e job* (nx-verdaccio) or *out-of-band post-publish* (analog). This repo already does the former on every PR.

## (5) "Test the exact artifact you publish" -- ecosystem norm + where it should run

**Norm:** `npm pack` + install-the-tarball is the accepted "test-what-you-ship" pattern (vs testing `src`/`dist` directly) -- it exercises the `files` whitelist, `main`/`types`/`exports`, and resolution as a consumer sees them. This repo does the *stronger* variant: publish to a local registry + install, which additionally exercises registry metadata + package-manager resolution (npm/pnpm/yarn, `ng add`, `nx add`). `dist/packages/angular-typechecker` is byte-for-byte the packageRoot `release.yml` builds and `nx release publish` ships.

**Where the provenance e2e should run:**
1. **Release-PR `ci.yml` (already happens) -- PRIMARY, no change.** The `release/x.y.z` -> `main` PR runs `ci.yml`, whose `install-e2e` cell builds+publishes+installs the exact dist. This proves the artifact **before** the tag push that fires `release.yml`. Zero new required check, zero release.yml change.
2. **Pre-publish job inside `release.yml` -- REJECTED.** Bloats a deliberately minimal, single-purpose, hardened workflow whose only elevated scope is `id-token: write`. Adding e2e (package managers, fixtures, Verdaccio, corepack) widens the attack surface of the one workflow that can publish. Do **not**.
3. **Separate post-publish real-npm smoke workflow -- RECOMMENDED ADDITIVE.** analog's `test-release.yml` model: `schedule` + `workflow_dispatch`, `contents: read`, installs from **real npm**. Catches the two things the local Verdaccio test cannot: (a) the actual npm-side packaging/dist-tag/resolution, and (b) the **provenance attestation** -- which `install-e2e/global-setup.ts:179-183` deliberately strips (`publishConfig.provenance = false`) for the local publish. This is a NEW, independent workflow; it does not touch `ci` or `release.yml`.

**Recommendation:** keep `release.yml`'s hardened publish job intact. Prove the exact artifact via the Release-PR `install-e2e` cell (in-band, pre-publish). Add the post-publish real-npm smoke as a **separate** workflow when you want to close the provenance-attestation + real-registry gap.

## (6) Synthesis -- concrete two-track design

### Track A -- fast PR CI (per-project dynamic matrix)

Status: measured ~353s / ~43% faster (CI run 29393040360). One refinement vs the MEASUREMENTS "consolidated architecture":

- **Drop the artifact upload/download** -- it is a proven no-op (nx rejects the cross-runner `.nx/cache`; the `dependsOn: build` rebuild happens anyway and is ~2-4s). Removing it deletes 2 SHA-pinned action refs and simplifies the build job to *discovery only*.
- **Keep a lean discovery job** for the dynamic matrix (the user's HARD auto-cover requirement). Two options:
  - `nx show projects --with-target e2e --json` (authoritative; needs `npm ci`, ~39s serial).
  - **Cheaper (recommended):** a tiny node/fs step that reads `e2e/*/project.json` and emits the `.name` of each project defining an `e2e` target -- identical output to `nx show`, no `npm ci`, ~5s, and it mirrors the guard's own `enumerateE2eProjects` logic. GUARD-01/01e already enforce the `.name === dir` + `e2e`-target invariants, so drift is caught.
- **Keep per-cell `dependsOn: build` + GUARD-01e.** Preserves local `nx run-many -t e2e` and the fresh-runner build edge.
- **`nx run-many -t typecheck -p <matrix.project>` + `nx run-many -t e2e -p <matrix.project>`** per cell (keep the `run-many` spelling for GUARD-01/01c).

ci.yml matrix sketch (discovery + fan-out; act-safe fallback in bold):

```yaml
  discover:
    needs: changes
    if: ${{ needs.changes.outputs.code != 'false' }}
    runs-on: ubuntu-latest
    outputs:
      projects: ${{ steps.list.outputs.projects }}
    steps:
      - uses: actions/checkout@<sha> # v7.0.0
        with: { persist-credentials: false }
      - id: list
        run: node tools/ci/list-e2e-projects.mjs >> "$GITHUB_OUTPUT"   # emits: projects=["...","..."]
  e2e:
    needs: [changes, discover]
    if: ${{ needs.changes.outputs.code != 'false' }}
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        project: ${{ fromJSON(needs.discover.outputs.projects || '[]') }}   # || '[]' keeps act -n green
    # ... checkout/setup-node/corepack/pnpm/npm ci ...
    # - run: npx nx run-many -t typecheck -p ${{ matrix.project }}
    # - run: npx nx run-many -t e2e -p ${{ matrix.project }}
  ci:
    needs: [changes, discover, test, e2e, fallow, format-lint, act-compat, lint-workflows, scoped-name-guard]
    # unchanged contains(needs.*.result,'failure'|'cancelled') gate
```

### Track B -- release provenance e2e

- **Primary (now, zero cost):** rely on the Release-PR `ci.yml` `install-e2e` cell. It already builds+publishes+installs `dist/packages/angular-typechecker` = the exact release artifact.
- **Additive (follow-up task):** a separate `test-release.yml` (`schedule` + `workflow_dispatch`, `contents: read`, SHA-pinned) that `npm install`s the published `angular-typechecker@latest` from real npm into a fresh Angular-CLI + a fresh Nx workspace and runs `nx typecheck`. Mirrors analog. Closes the real-registry + provenance-attestation gap the local Verdaccio test strips.

### Differentiation mechanism

Already achieved by trigger separation (tag -> release.yml; PR -> ci.yml). If you additionally want ordinary PRs *faster* by not running the heaviest provenance cells, gate them:

```yaml
# only fan out the heavy install/ng-cli provenance cells on the Release PR
# regular PRs run the lean matrix-e2e + cache-e2e; ci gate tolerates the skipped cells (D-08)
```
via `if: startsWith(github.head_ref, 'release/')` on the heavy cells OR a discovery job that emits a **different project list** for `release/*` head refs. **Honest tradeoff:** the current per-project matrix floor is `ng-cli-e2e` (312s) running concurrently with `install-e2e` (301s); dropping `install-e2e` alone saves **zero wall-clock** (ng-cli is the floor). To get real speed you must move **both** `ng-cli-e2e` and `install-e2e` (the two artifact-install suites) to release-only -- dropping regular-PR e2e to the `matrix-e2e`/`cache-e2e` floor (~80s). That is a large win but means a packaging/`ng add`/`nx add` break is caught on the Release PR, not the feature PR. **For a correctness tool, I lean KEEP full provenance on every PR (already fast) + add the post-publish smoke; treat the branch-gate as an explicit opt-in.**

### GUARD spec changes

- **GUARD-01b `--parallel=2` assertion:** rewrite (source change -> `/gsd-code-review`). A per-project matrix cell runs one project, so `--parallel=2` is gone from ci.yml. Replace that one `it(...)` with an assertion that the ci.yml matrix wiring is the dynamic `fromJSON(... --with-target e2e ...)` (or, for the fs-discovery variant, that the discovery script is invoked) AND that its output equals `enumerateE2eProjects()`. The other four GUARD-01b assertions (`--pack-destination`, install-e2e `parallelism:false`, cache-e2e `parallelism:false`, no-in-spec `nx build`) **stay** -- they protect the LOCAL full-tier `nx run-many -t e2e --parallel=2` run.
- **GUARD-01/01c/01d/01e:** unchanged (`run-many` spelling kept; per-cell `-p ${{ matrix.project }}` fine; `dependsOn: build` kept).
- **Job id must stay `e2e`** (`extractE2eJobLines` slices `^  e2e:$`).

### act / actionlint + required-check `ci` impact

- **Dynamic `fromJSON` matrix is the one real risk.** Under `act -n`, `needs.<discover>.outputs.projects` is empty and `fromJSON('')` throws during plan expansion. Mitigate with `fromJSON(needs.<discover>.outputs.projects || '[]')` (empty matrix under act = no cells, plan stays valid). **Validate with `bash tools/act/act-compat.sh` (container-free) before any CI run.** Harden the act-compat token from `ci/e2e` to `ci/e2e-` (match the family, per WR-02), since a matrix cell dry-runs as `[ci/e2e-1]` -- but an empty matrix under act emits no e2e cells, so if the act-compat suite asserts e2e is *selected*, prefer a static fallback list under act OR relax that assertion. Confirm behavior locally.
- **actionlint:** a well-formed `fromJSON` matrix + declared `needs` graph passes; the discovery job output must be declared under `outputs:`.
- **`ci` gate:** add `discover` to `needs`; the existing `contains(needs.*.result, 'failure'|'cancelled')` catches a discovery/cell/build failure. **No new required-check name; no ruleset edit.** A separate `test-release.yml` does not touch `ci`.
