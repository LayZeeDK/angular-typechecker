## OIDC publish contingency (empty-\_authToken trap)

| Option    | Description                                                            | Selected |
| --------- | ---------------------------------------------------------------------- | -------- |
| Reactive  | Attempt release.yml as-is; drop `registry-url` only if it 404s on auth | [X]      |
| Proactive | Drop `registry-url` before the first attempt                           |          |

**Choice (auto):** Reactive.
**Notes:** Research confirms `registry-url` + no token + npm >= 11.5.1 is the documented WORKING
OIDC config (release.yml already uses Node 24 + `npm i -g npm@latest`). The #1 cause of the
misleading 404 (old npm/Node) is already mitigated; exact-match config (repo casing, workflow
filename, repository.url) already correct from 05-05. The inline release.yml comment + ROADMAP
prescribe the reactive drop. A 404-on-auth means not published, so re-running same 0.0.2 is safe.
