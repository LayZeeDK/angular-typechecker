## Phase Goal

**As a** developer adopting angular-typechecker in an Nx workspace, **I want to** `npm install` the published package and have `nx run <project>:angular-typecheck` resolve and run the executor (and its types) from the installed package, **so that** I get the complete Angular type-check in CI/agent loops without building the app.

> Vertical-MVP tracer bullet (D-22): a clean `npm install <tarball>` resolves the executor and runs it. This plan (05-01) is the first slice -- making the published artifact (manifest + types) correct; 05-02 audits it, 05-03 proves install-and-run end-to-end, 05-04 hardens the release path, 05-05 is the human-gated live publish.
>
> User-story derived from the ROADMAP Phase 5 `**Goal**` (outcome-shaped: "publishable to npm and installs-and-runs end-to-end"). The consuming developer is the user role; this matches the established `Mode: mvp` outcome-goal convention of phases 1-4.

<objective>
Make the plugin manifest fully publishable and fix the one production-code defect that blocks a resolvable tarball. This is the first vertical-slice task toward "a clean install of the packed tarball resolves the executor and its types": after this plan, the SOURCE manifest carries the complete PKG-01 contract, a LICENSE ships, the README documents the real consumer recipe, and the shipped `.d.ts` surface no longer escapes the published package (D-10/B-02).

Purpose: A tarball whose manifest is incomplete (no `files` allowlist, no LICENSE, no `exports`/keywords/repository) is not registry-eligible or publishable; and a tarball whose types contain a deep-relative `node_modules` import does NOT resolve in a consumer install (empirically reproduced by `attw --pack` returning `InternalResolutionError` on all profiles). Front-loading both here lets plan 05-02 PROVE them against the packed artifact.

Output: An extended `package.json`, a per-package `LICENSE`, a LICENSE build asset (and the dead `generators.json` glob removed), a `checkVersionMismatches:false` ESLint option, a self-contained `compiler-cli-types.ts`, a fleshed-out README, and an extended `package-manifest.spec.ts` regression backstop.
</objective>
