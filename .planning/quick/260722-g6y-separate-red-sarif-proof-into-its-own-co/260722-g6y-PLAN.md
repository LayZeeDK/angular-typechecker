<objective>
Split the deliberate RED SARIF proof out of the dogfood Code Scanning tool: it uploads under
its own `driver.name` (D-02 `angular-typechecker-red-proof`), from a descriptively renamed job,
and passes only when the Code Scanning API reports EXACTLY the four expected diagnostics in the
expected files (D-03) -- after which it dismisses precisely those alerts (D-01).

Purpose: the fixture's four deliberate errors currently land under `angular-typechecker`, which
makes the dogfood check RED and re-posts unresolved review threads. Separating the tool makes
the dogfood check honest and the proof self-healing.

Output: a reworked `tools/ci/assert-code-scanning.mjs` (exact-set matcher + scoped, non-fatal
dismissal, unit-testable through the existing `ASSERT_ALERTS_FILE` seam), a renamed
`code-scanning-red-proof` job that post-processes the emitted SARIF's `driver.name`, and drift
guards updated to the new id.

ADDITIVE-ONLY charter holds: `package.json`, `src/core/**`, `src/cli/**` stay byte-unchanged
(the only `src/core/**` touch is a comment-only job-id rename in an existing spec), version
stays `0.2.3`, no release cut. The shipped CLI is NOT modified -- the tool rename is a CI-side
post-process of the SARIF the CLI already emits.
