<objective>
Fix the Release-PR-blocking e2e-CI regression: on a fresh runner `nx run-many -t e2e` never builds
`dist/packages/angular-typechecker`, so every e2e globalSetup ENOENTs on the built package.json. Root
cause (orchestrator-verified against nx source): all four e2e targets use `executor: "@nx/vitest:test"`,
and nx's `readTargetDefaultsForTarget` returns the EXECUTOR-keyed default and short-circuits BEFORE
reading the NAME-keyed `e2e` default -- so the entire `e2e` targetDefault (with its
`dependsOn: ["angular-typechecker:build"]`) is silently discarded. Neither `angular-typechecker:build`
nor `^build` under the name key can ever apply.

The fix (research-empirically verified to schedule ONE shared build before the parallel tier):
(1) DELETE the inert name-keyed `e2e` targetDefault from nx.json; (2) ADD
`dependsOn: [{ "projects": ["angular-typechecker"], "target": "build" }]` to the `e2e` target in EACH
of the four e2e project.json files -- a target's OWN config always applies (most specific), bypassing
the executor-key precedence trap. This fixes BOTH CI (fresh runner builds dist first) AND local
`nx run-many -t e2e`, and preserves squ's build-once-before-parallel intent (nx dedups to a single
`angular-typechecker:build` task; the four e2e tasks then run at --parallel=2 against a read-only dist).
Guard it with GUARD-01e (pure-FS read of each e2e project.json's `e2e` target dependsOn), then VERIFY
with the cheap fresh-dist repro and an act fresh-container e2e run.

Purpose: unblock the Release PR (the e2e tier is the gate that proves the PUBLISHED tarball works) and
make the build-ordering invariant self-guarding so this exact inert-config trap cannot silently return.
Output: nx.json + 4 project.json config edits, GUARD-01e in the coverage-guard spec, a comment-only
ci.yml correction, and a SUMMARY.md.
</objective>
