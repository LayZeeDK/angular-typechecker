<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test process -> local Verdaccio registry (127.0.0.1) | The publish-once flow writes the built artifact to a local registry; a misconfigured registry URL could leak a publish to the public npm. |
| test process -> installed CLI (OS process boundary) | The `.bin` shim is spawned as an OS process; `npx` name resolution can fetch a foreign package. |
| consumer fixture install -> npm registry | The nested install must resolve ONLY from Verdaccio, not an inherited public registry. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-02 | Elevation of Privilege / Repudiation | global-setup.ts -> createVerdaccioGlobalSetup publish | mitigate | Reuse the verbatim SAFETY refuse-gate: createVerdaccioGlobalSetup refuses any registry not starting `http://127.0.0.1:` before `nx release publish` (D-01/D-02). Each spec re-asserts `verdaccioUrl.startsWith('http://127.0.0.1:')`. |
| T-28-03 | Malicious code / Supply chain | cli-exit-codes.e2e.spec.ts npx cell | mitigate | Invoke the installed `.bin/atc` shim BY PATH via runShim; use ONLY `npx angular-typechecker` for the npx path (package name matches a bin name -> always resolves this package). NEVER `npx atc` (would fetch the unrelated `atc@0.0.6`). Enforced by source grep in acceptance criteria. |
| T-28-06 | Information disclosure / Tampering | consumer fixture nested install | mitigate | `buildCleanEnv({ stripAllNpmConfig: true })` + `npm_config_userconfig` -> nonexistent path so an inherited `npm_config_registry` cannot leak the install to the public registry (install resolves only from Verdaccio via the tmp `.npmrc`). |
</threat_model>
