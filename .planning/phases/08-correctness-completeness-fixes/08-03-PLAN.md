<objective>
COR-03 + COR-04: (a) A diagnostic whose `file.fileName` is present-but-empty is treated
as file-less (reported, never silently dropped by the project-boundary filter); (b) the
engine exposes a pure, framework-agnostic exit-code policy `toExitCode` (0 clean / 1
type-error / 2 infra, ngc-parallel) as the single source of truth for all surfaces.

Purpose: COR-03 closes a false-negative: today an empty `fileName` canonicalizes to `''`
and `isUnderDir('', base) === false` suppresses it (a real error suppressed by a path
edge). COR-04 makes the infra-vs-type classification explicit and pure so the (deferred)
standalone CLI can deliver the literal OS exit code `2` from the same definition, while
the Nx executor stays bound to its `{ success }` -> 0/1 contract (D-08).

Output: One widened boolean in `filter-diagnostics.ts` + a unit case; a new pure
`core/exit-codes.ts` (mirroring `evaluate-result.ts`) + its unit spec; and an optional
tightening of the existing executor infra-catch assertion. These are two pure-policy /
leaf changes grouped because they share zero files with the other plans and with each
other, and neither requires touching `run-typecheck.ts` or `executor.ts` source.
</objective>
