<objective>
Widen the shipped SARIF reporter so every diagnostic that fires resolves to a cataloged
SARIF rule carrying a diagnostic-family tag (RULE-02), the correct default severity level
(RULE-03), and inline help text (RULE-04) -- across ALL families -- by flipping the rule
catalog from the fixed 18 NG8xxx entries to one rule per DISTINCT fired ruleId (RULE-01).

Purpose: today a GitHub Code Scanning alert for a TypeScript, template, or tool diagnostic
shows a blank rule description, cannot be grouped with a `tag:` filter, and renders
"No rule help available". This plan closes all four gaps in the SARIF path only.

Output: a new pure classifier module (D-01), a rewritten rule-catalog pass in
`sarif-report.ts` (D-05, D-06, D-07, D-08, D-09), a corrected module header (D-11), and the
unit specs plus regenerated snapshot that encode the release-bearing delta. JSON and human
output stay byte-identical (D-12); `extended-catalog.ts` stays byte-unchanged (D-10); no new
dependency (D-09).
</objective>
