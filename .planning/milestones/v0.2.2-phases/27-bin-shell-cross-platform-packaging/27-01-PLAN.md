    Call `run(process.argv.slice(2))` and chain `.then` / `.catch` (top-level await is ILLEGAL here -- `package.json` is `type: commonjs` and this compiles `module: nodenext`; use `.then/.catch`, per RESEARCH lines 233-236).

    In `.then(({ exitCode, stdout, stderr }) => {...})`: if `stdout` is truthy call `process.stdout.write(stdout)`; if `stderr` is truthy call `process.stderr.write(stderr)`; then set `process.exitCode = exitCode` and RETURN. Setting `process.exitCode` + letting the event loop drain is the flush-safe idiom.

    In `.catch((error: unknown) => {...})`: write `String((error as { stack?: string })?.stack ?? error) + '\n'` to `process.stderr` and set `process.exitCode = 2` (D-03: `run()` re-throws any non-`TypecheckInfrastructureError`; an unknown crash is infrastructure-class for a type-checker -> exit 2, never 0/1).

    Apply the repo JS/TS style: blank lines around the `if` blocks and returns inside `.then`; braces on every control-flow body.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shell -> bin.ts (process.argv) | Untrusted CLI args cross into the process. bin.ts forwards them to run(), which reads tsconfigs via the ts/fs API -- never a shell. |
| bin.ts -> npm/pnpm/yarn `.bin` shim | The `bin` field is what PMs turn into installable command shims. |
| build host -> published bin.js | The compiled shebang must survive with LF bytes to run on Linux/macOS. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-01 | Tampering | `bin.ts` shebang (CRLF on the Windows arm64 build host) | mitigate | `newLine: lf` in tsconfig.lib.json (primary) + `*.ts text eol=lf` .gitattributes (belt-and-suspenders); proven by 27-02's dist byte-check. |
| T-27-02 | Denial of Service | `src/cli/**` import graph reaching `@nx/*`/nx (the 24-06 chalk-chain crash class on a non-Nx consumer) | mitigate | `src/cli/**` ESLint import-ban (this plan, Task 3); static require-graph walk (27-02). |
| T-27-03 | Elevation of Privilege / Spoofing | `atc` bin name (unrelated `atc@0.0.6` exists on npm) | accept (informational) | This plan only ships both bin names. Docs steer to `npx angular-typechecker` (Phase 29); `--help` already does so (Phase 26 D-11). Not HIGH -- naming only. |
| T-27-04 | Tampering | `process.exit` truncating a piped stdout tail (a dropped `TSxxxx` code = a silent wrong verdict on a pipe) | mitigate | D-02: `process.exitCode` + natural drain, NEVER `process.exit` (Task 1). |
| T-27-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs this phase (zero new dependency/dev-dependency); nothing to slopcheck. `bin.ts` adds only a `node:*`/pure-core import graph. |

No HIGH-severity threat found: this is a dev-tool CLI that reads tsconfigs via ts/fs (no shell-out of user input), writes stdout/stderr, and ships a bin with no install lifecycle scripts and no network/secrets.
</threat_model>
