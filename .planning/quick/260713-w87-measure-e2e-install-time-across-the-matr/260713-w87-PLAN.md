  <name>Task 1: Add opt-in install timing to sh() + a committed aggregator, prove no-op when unset</name>
  <files>libs/test-util/src/lib/e2e-process.ts, libs/test-util/src/lib/e2e-process.spec.ts, tools/e2e-timing/aggregate-install-timings.mjs</files>
  <behavior>
    - When process.env.ATC_TIME_INSTALLS !== '1': sh() writes NO timing file and
      behaves byte-for-byte as today (same returned stdout on success, same thrown
      Error message on failure). No performance.now() call, no appendFileSync.
    - When process.env.ATC_TIME_INSTALLS === '1': after each sh() call (BOTH the
      success and the catch path, before rethrow), one JSONL line is appended:
      { ts: Date.now(), cmd: <command>, cwd: <options.cwd>, ms: <rounded elapsed>, ok: <boolean> }.
    - Output path = process.env.ATC_TIMING_OUT ?? join(os.tmpdir(), 'atc-install-timings.jsonl').
      An absolute ATC_TIMING_OUT wins.
    - Append mode (appendFileSync) so concurrent --parallel=2 specs do not clobber.
    - The line AND its trailing newline are written in ONE call:
      appendFileSync(path, JSON.stringify(record) + '\n'). NEVER a split write (a
      split write reopens the interleave window under --parallel=2 and can corrupt a
      neighboring line).
  </behavior>
  <action>
    DECISION (state it in the SUMMARY): the sh() timing is COMMITTED opt-in --
    genuinely additive and no-op when the flag is unset, and test-util is a
    test-only library that is NOT shipped in the published tarball, so committing
    it is safe and reusable. The aggregator is COMMITTED under tools/ to keep the
    reusable opt-in whole.

    In `libs/test-util/src/lib/e2e-process.ts`: add a small private helper (e.g.
    recordInstallTiming) that appends the one JSONL line described in <behavior> in
    a SINGLE appendFileSync call (record + '\n' concatenated before the call),
    guarded so it is only ever called when process.env.ATC_TIME_INSTALLS === '1'.
    Use `appendFileSync` from node:fs, `tmpdir` from node:os, `join` from node:path,
    and the global `performance` for elapsed ms. Wrap the existing execSync in sh():
    capture `started = process.env.ATC_TIME_INSTALLS === '1' ? performance.now() : 0`
    before the try; on success capture stdout in a local, record ok:true, return it;
    in the catch, record ok:false BEFORE building and throwing the existing Error.
    Keep the unset path with zero new work (no performance.now, no write) so it is
    byte-identical to today. Do NOT touch run(), buildCleanEnv, commandSucceeds,
    removeTmpDir, the barrel, or the sh() signature.

    Create `libs/test-util/src/lib/e2e-process.spec.ts` (match the vitest style of
    find-workspace-root.spec.ts): drive sh() against a trivial always-succeeding
    command (e.g. `node -e ""` or a `--version` probe) in an OS-temp cwd, with
    ATC_TIMING_OUT pointed at a unique temp file. Cases: (1) flag UNSET -> the temp
    file does NOT exist after the call and stdout is returned normally; (2) flag SET
    -> the temp file exists and its last JSONL line parses to an object carrying
    cmd/cwd/ms/ok with ok:true; (3) flag SET on a failing command -> sh() still
    throws with the command in the message AND a line with ok:false is appended.
    Restore process.env.ATC_TIME_INSTALLS / ATC_TIMING_OUT in afterEach so cases do
    not leak into each other. Clean up the temp file.

    Create `tools/e2e-timing/aggregate-install-timings.mjs`: a standalone Node ESM
    CLI. Read the JSONL path from argv[2] ?? join(os.tmpdir(), 'atc-install-timings.jsonl'),
    split into lines, JSON.parse each non-empty line, and group by (PM, scenario,
    action). Derive:
      - action = a normalized label from cmd (npm install / pnpm install /
        corepack yarn install / nx add / ng add / npm install <tgz> / pnpm add <tgz> /
        storybook install / other).
      - PM (order matters -- check these prefixes IN ORDER):
          1. cmd starts with `corepack yarn` OR `yarn` -> PM = yarn. This MUST come
             before any generic "leading token" check: `corepack yarn install` (the
             HEAVIEST yarn workload: the full Angular 22 ng-cli fixture) has leading
             token `corepack`, so a naive leading-token rule would misfile it as
             `corepack`/`other` and corrupt the per-PM yarn total. Special-case it.
          2. cmd starts with `pnpm` -> PM = pnpm.
          3. cmd starts with `npm` -> PM = npm.
          4. otherwise (`nx add` / `ng add` / a bare `npm install <tgz>` whose PM is
             ambient) -> derive PM from the cwd basename prefix: atc-*-yarn / atc-ng-yarn-*
             -> yarn; atc-*-pnpm / atc-ng-*-pnpm -> pnpm; else -> npm.
      - scenario = the cwd basename with the random mkdtemp suffix trimmed to its
        `atc-<name>` prefix.
    Emit a GitHub-flavored markdown table (columns: PM, scenario, action, count,
    total ms, mean ms, max ms) sorted by total ms desc, plus a per-PM totals table
    and a grand total, to stdout. Best-effort: parse each line inside try/catch, skip
    unparseable lines with a stderr note; never throw on a malformed line. Keep it
    short (~60-90 lines).

    STYLE (all three files): Prettier singleQuote, ASCII only (no emojis/unicode),
    braces on every control-flow body, blank lines around control flow and returns.
    tools/ is NOT in .prettierignore, so the .mjs is format:check'd -- keep it clean.
    ponytail: the aggregator is a legit manual dev-tool CLI (never imported); if a
    future release PR's fallow new-only gate flags it as unreferenced, add its path
    to .fallowrc.jsonc entryPoints then -- do NOT pre-edit fallow config now (branch
    pushes do not run CI).
  </action>
