<objective>
Ship the VER-04 guards that PROVE Phase-31's lazy SARIF boundary: (a) a static
require-graph guard that the human / JSON / `--help` / CLI-boot paths never load
`node-sarif-builder` (nor its transitive `fs-extra`), (b) a REAL-import (not mocked)
interop test that the CJS-under-`await import()` shape resolves via `(mod.default ??
mod)` and builds SARIF 2.1.0, and (c) resolve `@nx/dependency-checks`' visibility of the
lazy-only dynamic import against the REAL `nx lint`.

Purpose: the lazy `await import()` firewall is only a startup-leanness/supply-chain win
if it is LOCKED -- an accidental top-level `import 'node-sarif-builder'` would silently
pull the dep (+ `fs-extra`) onto every human/JSON/boot run. These guards make that
regression fail loudly, and the real-import test catches an interop break a mocked unit
test cannot (Pitfall 9).
Output: `core/sarif-require-graph.spec.ts`, `core/sarif-report.interop.spec.ts`, and the
resolved dependency-checks decision (a one-line `ignoredDependencies` entry only if the
real lint requires it).

does `await import('./sarif-report')`, and the interop spec imports the `node-sarif-builder`
dependency 31-01 declared + installed.
