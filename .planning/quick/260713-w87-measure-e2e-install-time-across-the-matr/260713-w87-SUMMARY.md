# Quick Task 260713-w87: Measure e2e install time across the PM matrix Summary

Instrumented the single shared e2e install seam (`sh()`) with opt-in, no-op-when-unset
timing, added a committed JSONL aggregator, ran the tier once instrumented, and compiled
`260713-w87-MEASUREMENTS.md` mapping the measured install hotspots to the RESEARCH ranked
levers (top follow-up = persist the Verdaccio uplink cache). MEASURE + REPORT only -- no
optimization applied.

## What was done

### Task 1 -- opt-in sh() timing + aggregator (committed `1b88529`)

- `libs/test-util/src/lib/e2e-process.ts`: `sh()` appends one JSONL record
  `{ ts, cmd, cwd, ms, ok }` per call ONLY when `ATC_TIME_INSTALLS === '1'`, via a
  single `appendFileSync(record + '\n')` (no split write -> no `--parallel=2`
  interleave). Path = `ATC_TIMING_OUT` (absolute wins) or OS-tmpdir default. Unset path
  is a true no-op: no `performance.now()`, no write, byte-identical returned stdout and
  thrown Error text. `run()`, `buildCleanEnv`, `commandSucceeds`, `removeTmpDir`, the
  barrel, and the `sh()` signature are all untouched.
- `libs/test-util/src/lib/e2e-process.spec.ts`: proves (1) UNSET -> no file written +
  stdout returned; (2) SET -> a well-formed `ok:true` line; (3) SET on a failing command
  -> still throws with the command in the message + an `ok:false` line.
- `tools/e2e-timing/aggregate-install-timings.mjs`: tolerant per-line JSON.parse
  (skips malformed lines, never throws), ORDERED PM rule that files `corepack yarn
  install` under yarn (before any leading-token check), cwd-basename fallback for
  ambient `nx add` / `ng add` / bare-tarball installs; emits per-(PM x scenario x
  action) + per-PM totals + grand total.

Gates (flag UNSET, the runner's normal mode): `nx test test-util` 7/7, `nx lint
test-util`, `nx typecheck test-util`, `nx format:check` on all 3 files -- ALL GREEN.
Aggregator sanity-checked on a synthetic JSONL (corepack-yarn bucketed to yarn; broken
line skipped; exit 0).

### Task 2 -- instrumented run + report (docs, uncommitted)

- Ran once: `ATC_TIME_INSTALLS=1 ATC_TIMING_OUT=$PWD/tmp/e2e-install-timings.jsonl
  NX_DAEMON=false npx nx run-many -t e2e --parallel=2 --skip-nx-cache`. All 4 e2e
  projects passed (exit 0); the known ng-cli local-registry flake did not occur (no
  re-run needed).
- Wrote `260713-w87-MEASUREMENTS.md`: methodology, the Windows-arm64-vs-CI-Linux caveat
  (Defender + corepack spawn tax inflate absolutes; single run -> directional), the
  per-PM x per-scenario x action tables + totals, coverage confirmation, and the
  hotspot -> ranked-lever mapping (Lever 1 Verdaccio warm-cache top, Lever 2 CI cache,
  Lever 5 yarn-cache trap, honest irreducible-bytes ceiling).

### Headline numbers (directional; Windows arm64 dev box)

- Per-PM `sh()` install-seam totals: npm 593637 ms (26 calls), yarn 208868 ms (11),
  pnpm 85126 ms (9). Grand total 46 calls, 887631 ms. (Per-PM totals are NOT a PM race
  -- npm runs the most scenarios.)
- Heaviest single install: `corepack yarn install` of the ng-cli Angular 22 fixture,
  flat layout, 93.4s cold. Same fixture/PM on the workspace layout (second, warmer
  Verdaccio) = 43.8s -- a ~2.1x in-run cold/warm delta that is a concrete lower bound
  for the Lever 1 win.

## Deviations

- **pnpm-symlink measured via a temporary, reverted local edit (prompted mid-task).**
  matrix-e2e's `pnpm-symlink` spec installs `pnpm add <tgz>` through a DIRECT `execSync`
  (its catch needs `status`/`signal` discrimination that `sh()`'s plain-Error rethrow
  does not preserve), so it bypasses the committed seam by design. To measure it without
  altering the shipped spec, its install was wrapped with the same timing-record shape,
  matrix-e2e was re-run standalone (Verdaccio up via global-setup -> same cold-uplink
  context), the `atc-pnpm | pnpm add <tgz> | 7166 ms` record was appended to the JSONL,
  and the spec edit was REVERTED (git-clean; verified no `appendFileSync`/`ATC_*`
  leftover). The report's numbers were regenerated to include it.
