      `Object.assign(new Error('disk full'), { code: 'ENOSPC' })`) on

    (braces + blank-line style per repo rules). Attach it to BOTH streams --
    `process.stdout.on('error', ignoreEpipe)` and
    `process.stderr.on('error', ignoreEpipe)` -- at module load, textually ABOVE the
    existing `run(process.argv.slice(2))` chain so it is registered before any write
    can fail. Doc-comment rationale to encode (matching bin.ts's existing heavy
    comment style, ASCII only): the reader closing the pipe (e.g.
    `atc -c tsconfig.json | head`) raises an async 'error' with code EPIPE on the
    stream; `process.exitCode` is already set synchronously in the .then/.catch

    verdict instead of dying with an uncaught `write EPIPE` stack + wrong exit code

    process.exit()" rule (Pitfall 6). Any NON-EPIPE stream failure is RE-THROWN so
    it stays loud.

    tests above, following the existing mock-'./main' + dynamic-import + flush()
    pattern already in the file. CRITICAL cleanup (mirrors the file's existing
    process.exitCode save/restore care): each `import('./bin')` under
    vi.resetModules attaches FRESH listeners to the real process streams, so
    snapshot `process.stdout.listeners('error')` and
    `process.stderr.listeners('error')` in beforeEach, and in afterEach remove any
    listener present then but absent from the snapshot
    (`process.stdout.removeListener('error', l)` for each newly-added `l`) so
    nothing leaks into vitest's own process across tests/files. Note: the existing
    `vi.spyOn(process.stdout, 'write')` mock returns true, so no REAL stream error
