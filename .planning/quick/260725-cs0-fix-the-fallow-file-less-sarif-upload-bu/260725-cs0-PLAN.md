# Quick Task 260725-cs0: Fix the fallow file-less SARIF upload bug

## Context

`ci.yml`'s `code-scanning` job uploads fallow's multi-run SARIF. The `fallow audit` **dupes
sub-analysis** emits a `fallow/code-duplication` result with the `locations` key **omitted
entirely**, and GitHub rejects the **ENTIRE upload** with `locationFromSarifResult: expected at
least one location` -- so one file-less clone-group finding loses every fallow alert, including the
sibling dead-code run's 84 properly-located ones. Proven twice in live CI (runs `30004691193`,
`29772473095`; zero fallow analyses exist at the failing commit).

Settled by research, do not re-derive:

- **Not fixable upstream or by config.** `fallow config-schema` exposes no `sarif` / `location` /
  `anchor` knob, and fallow **3.9.1** (latest; 3.6.0 pinned) reproduces byte-identically. **Do not
  bump fallow** as part of this fix.
- **A SARIF post-process cannot recover a real file.** The offending result carries no file
  information at all -- clone-group instance paths exist only in `fallow --format json`. A
  repo-level anchor is the only option.
- **Region-less locations ARE accepted by GitHub**, proven by the Phase 35 `ATC90002` alert landing
  at `tsconfig.json` with GitHub back-filling the region to line 1 col 1, despite the docs marking
  `region.startLine` Required. A bare `physicalLocation.artifactLocation.uri` suffices.
- **Anchor: `.fallowrc.jsonc`** -- the file whose `duplicates.ignore` a maintainer edits to act on a
  clone group, mirroring fallow's own convention of anchoring project-level findings at
  `package.json`, and this repo's own file-less precedent (`sarif-report.ts` anchoring at
  `tsConfigPath`, region-less).
- **The `automationDetails` overwrite is LOAD-BEARING.** fallow now sets its own
  `fallow/audit/dupes` id; GitHub derives the category from the text before the final `/`, so
  leaving it would yield category `fallow/audit` -- a NEW tuple, i.e. exactly the orphaned-config
  hazard in AGENTS.md GATE-02 step 0. Port the stamping loop verbatim.

Lazier alternative, rejected: keep the post-process inline in `ci.yml`. CONTEXT.md decision 1 and
CLAUDE.md's inline-`-e` rule both forbid growing that one-liner, and a CI-only-observable fix cannot
be regression-tested.

## Tasks

### Task 1: Add `tools/ci/normalize-fallow-sarif.mjs`

**Files:** `tools/ci/normalize-fallow-sarif.mjs` (new)

**Action:** Mirror `tools/ci/merge-sarif.mjs`'s shape exactly: a house-style header comment block, a
pure exported transform with JSDoc types, then a thin I/O wrapper guarded by
`if (process.argv[1] === fileURLToPath(import.meta.url))`. Node builtins only (`node:fs`,
`node:url`); no new dependency.

Two module constants: `const FALLBACK_URI = '.fallowrc.jsonc';` -- keep the anchor in this ONE named
constant so the REAL-CI-ONLY dotfile risk below is a one-line swap to `package.json` -- and
`const SARIF_FILE = 'fallow.sarif';`.

Export `normalizeFallowSarif(doc)`, which walks `doc.runs ?? []` and per run at index `i`:

1. Sets `run.automationDetails = { id: 'fallow/' + i }`. This is the verbatim port of the inline
   `node -e` it replaces and deliberately overwrites fallow's own id -- comment WHY (the category is
   the text before the final `/`; changing the scheme orphans the existing analysis tuple).
2. For each `result` of `run.results ?? []`, when NO entry of `result.locations` has a non-empty
   string at `physicalLocation.artifactLocation.uri`, assigns
   `result.locations = [{ physicalLocation: { artifactLocation: { uri: FALLBACK_URI } } }]` --
   region-less on purpose. One condition covers all three deficiency shapes (`locations` key absent,
   `locations: []`, an entry lacking `physicalLocation`); only the first is observed, the others are
   free to cover and cheap insurance against a future fallow renderer change.
3. Never drops a result, and leaves a MIXED array (at least one usable entry) untouched -- unobserved
   shape, so minimal blast radius.

Returns `doc`. The wrapper reads `SARIF_FILE` relative to `process.cwd()`, calls the transform, and
writes it back with un-indented `JSON.stringify` (matching `merge-sarif.mjs`).

Comment the WHY inline in this repo's style, not just the what: the dupes run emits
`fallow/code-duplication` with no `locations` in fallow 3.6.0 AND 3.9.1; GitHub rejects the WHOLE
multi-run upload with `locationFromSarifResult: expected at least one location` (fired in CI runs
`30004691193` and `29772473095`); the clone group's instance files exist only in `--format json`, so
no post-processor can anchor at a real source file; region-less is proven accepted (the `ATC90002`
precedent, back-filled to line 1 col 1); `.fallowrc.jsonc` is where a maintainer acts on a clone
group; and the id scheme is frozen by the orphan-tuple hazard.

**Verify:**
- `node --check tools/ci/normalize-fallow-sarif.mjs` exits 0.
- `npx prettier --check tools/ci/normalize-fallow-sarif.mjs` passes.
- (Functional proof lands in Task 2 -- do not hand-roll a throwaway smoke script here.)

**Done:** The script exists, exports `normalizeFallowSarif`, parses clean as ESM, is Prettier-clean,
and its header states the four load-bearing whys (whole-upload rejection, no recoverable file,
region-less acceptance, frozen id scheme).

Fixture: one valid SARIF 2.1.0 envelope (`version`, a `$schema` string, `tool.driver.name` and a

## Commit type: `ci(...)` or `test(...)` -- NEVER `fix`

Use `ci(...)` (or `test(...)` for a spec-only commit). Do NOT use `fix`.

Attribution is decided by the FILES a commit changes, not by the scope text (AGENTS.md). Task 2's
spec lives at `packages/angular-typechecker/src/normalize-fallow-sarif.spec.ts` -- INSIDE the
released project's root -- so a commit touching it DOES count toward `angular-typechecker`'s
conventional-commits attribution. In 0.x, `fix` is a bump type (patch), so `fix(ci): ...` would
silently bump the released version at the next `nx release` and contradict this task's
no-version-bump intent. `ci` and `test` are no-bump types, and they match this repo's established
convention for exactly this change shape (e.g. `ci(36-01): promote Code Scanning jobs...`,
`test(36-02): lock the DOC-01...`).

Keep the scope release-meaningful (`ci`), never an internal plan id -- scopes leak verbatim into the
public changelog.
