<objective>
Ship the `configuration` generator (`nx g angular-typechecker:configuration <project>`) — the one command a developer runs to wire a project's `typecheck` target. It (1) awaits the `init` generator FIRST (so caching is seeded, GEN-08/D-10), (2) reads the project config, (3) resolves the target's `tsConfig` (explicit override -> solution `tsconfig.json` with `references[]` -> flat-project leaf fallback -> clear error), (4) collision-checks by executor, (5) writes ONE minimal target `{ executor: 'angular-typechecker:typecheck', options: { tsConfig } }`, and (6) formats once. Config-edit only (`project.json` + `nx.json` via `init`), NO `generateFiles`, idempotent, non-ours-collision-safe.

Purpose: Deliver GEN-01 (target write via devkit, no emission), GEN-02 (ONE target at the solution tsconfig + `--tsConfig` override + flat fallback + configurable `targetName`), GEN-03 (spec-tsconfig checking is automatic via the WALK-01 walk when pointed at the solution tsconfig; flat-fallback spec-checking left to the consumer), GEN-04 (idempotency + non-ours collision error), GEN-08 (`configuration` invokes `init`), plus its slice of GEN-05 (schema pair) and GEN-06 (in-memory unit tests + parity spec).

Its `src/generators/configuration/` directory layout mirrors the shipped executor tier (D-01). Output: `packages/angular-typechecker/src/generators/configuration/` populated with `generator.ts`, `schema.json`, `schema.d.ts`, `configuration.spec.ts`, `schema-parity.spec.ts`.
</objective>
