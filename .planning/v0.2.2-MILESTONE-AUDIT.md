## Notable milestone findings

1. **A true third adapter, proven structurally.** The standalone CLI composes the SAME
   `runTypecheck` core (byte-identical `evaluateResult().success` verdict) as the Nx executor and
   the `convertNxExecutor`-derived Angular CLI builder — confirmed by identical module imports and
   step-for-step pipeline parity, not by phase docs. The only differences are the three
   adapter-specific seams: sink (BufferingLogger vs `@nx/devkit.logger`), path resolution
   (`realpathSync.native` vs `joinPathFragments`), and return shape (`{exitCode,stdout,stderr}` vs
   `{success}`).
2. **The Phase-25 seam extraction paid off exactly as designed.** Pulling the five advisory
   `warn*` helpers into a pure, Logger-injected `core/emit-advisory-notices.ts` let the CLI reuse
   them without ever importing `executor.ts` (which would drag `@nx/devkit`/`chalk` — the 24-06
   crash class). Both adapters now drive one `emitAdvisoryNotices(result, logger)` call.
3. **The exit-code owner was scaffolding that never became load-bearing.** `toExitCode` — reserved
   since v0.0.3 COR-04 as the deliberate hook for "the deferred CLI" — was, once the CLI landed,
   found to be unreachable: the anti-false-pass design routes the 0/1 verdict through
   `evaluateResult().success` and the only literal-2 exits (usage + infra) are unconditional. The
   module was dropped (b44bd55) and the two `2`s inlined. The contract the requirement text
   attributes to `toExitCode` is fully preserved by the inline literals; only the mechanism name
   changed. (This is the correction to the prior audit, which recorded `toExitCode` as newly
   live.)
