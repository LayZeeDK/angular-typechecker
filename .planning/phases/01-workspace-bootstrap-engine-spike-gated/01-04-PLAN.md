into automated Vitest assertions, run the full build+test suite, and record the GO/NO-GO decision.

Angular 22 workspace before Phase 2 commits to the engine: (A) CJS-loads-ESM `import()` survives
`module: nodenext` emit, and (B) the unconditional all-getter surfaces template + extended (NG8109)
diagnostics even with a co-located TS error -- something `ngc`'s phase-short-circuiting default
gatherer provably does not (the differential is load-bearing). GO iff all six items hold; else NO-GO
-> revisit the engine/module decision before Phase 2.

Output: a green `npx nx build angular-typechecker && npx nx test angular-typechecker`, a recorded
cold-run timing, and an explicit GO/NO-GO statement in the SUMMARY.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| built artifact (untrusted emit) -> GATE A static spec | the spec reads the compiled `.js` from disk and asserts on its bytes |
| ESM compiler-cli load -> GATE B runtime guard | a failed `await import()` could surface as a fake diagnostic (code 500) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-10 | Information Disclosure | A masked ESM-load failure (`UNKNOWN_ERROR_CODE` 500) is mistaken for a passing GATE B run | mitigate | GATE B asserts `not.toContain(500)` and that the run resolves (no `ERR_REQUIRE_ESM`), so a hidden load failure fails the gate rather than silently passing (Pitfall 6) |
| T-01-11 | Tampering | A comment containing `import(` false-passes the GATE A regex against a downleveled artifact | mitigate | The GATE A spec strips `//` comment lines before matching, and asserts the `require('@angular/compiler-cli')` NEGATIVE as a second independent check |
| T-01-12 | Repudiation | A NO-GO gate result is silently advanced to Phase 2 | mitigate | Task 3 writes an explicit GO/NO-GO statement against all six items; the GATED roadmap note blocks Phase 2 on criteria 2 and 3 |
| T-01-SC | Tampering | npm install during test runs (supply chain) | accept | No new packages; tests resolve from the locked lockfile; official packages only (V14, covered by Plan 01's legitimacy audit) |
</threat_model>
