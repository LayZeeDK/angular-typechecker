<objective>
A standalone `tsc --noEmit -p e2e/angular-typechecker-install-e2e/tsconfig.spec.json`
reports `inject()` -> `never` (TS2345/TS2339) on every install-e2e spec, and NO CI
gate type-checks e2e source at all. Root cause (VERIFIED in RESEARCH.md, do not
re-derive): the spec tsconfig omits `src/global-setup.ts`, so the
`declare module 'vitest' { interface ProvidedContext { ... } }` augmentation at
global-setup.ts:187-192 is not in the tsc program, leaving `keyof ProvidedContext`
= `never`. Including global-setup.ts surfaces a SECOND real latent error: line 5
imports `GlobalSetupContext`, which vitest 4 removed (its successor is
`TestProject`, exported from `vitest/node`).

The fix (settled in RESEARCH.md): (1) point global-setup.ts at `TestProject`,
(2) add `src/global-setup.ts` to the install-e2e `tsconfig.spec.json` include,
(3) add a distinct `typecheck-e2e` `nx:run-commands` target (`tsc --noEmit -p ...`)
to all three e2e project.json files, (4) run it once in the existing CI `e2e` job.

RESEARCH verified: step (1)+(2) yields `tsc --noEmit -p tsconfig.spec.json` = exit 0;
cache-e2e and matrix-e2e already type-check clean (exit 0) so their targets pass
from the start.

Purpose: make the e2e specs + global-setup type-check cleanly AND keep it enforced
by a CI gate.
Output: the type fix + a `typecheck-e2e` gate on all three e2e projects, wired into CI.
</objective>
