<decisions>
## Implementation Decisions

### Rename strategy
- **D-01 (Hard rename, no back-compat alias):** The old id
  `angular-typechecker:angular-typecheck` is removed cleanly; NO deprecated alias
  / duplicate `executors.json` key / "renamed" error shim is added. The entire
  milestone is predicated on this being a genuine BREAKING change (drives
  `0.0.3 -> 0.1.0`); an alias would defeat that intent and add machinery Nx has no
  first-class support for. (ROADMAP SC5, PROJECT.md Key Decisions, REQUIREMENTS
  EXEC-01 all lock "breaking".)
- **D-02 (Full identity rename incl. directory + `$id` + internal symbols):**
  Rename the implementation directory with `git mv` (preserve history), the schema
  `$id` `AngularTypecheckExecutorOptions` -> `TypecheckExecutorOptions`, and the
  matching TS options-interface name, so **no stale `angular-typecheck` executor
  reference remains in shipped source** (SC1 + SC4). The schema `title`
  ("Angular type-check executor") is descriptive prose (no `angular-typecheck`
  token) and stays.

### Rename discipline (LANDMINE)
- **D-03 (Anchor every replacement; never a bare global replace):** `angular-typecheck`
  is a PREFIX of the package name `angular-typechecker`, so a naive
  `angular-typecheck` -> `typecheck` sweep corrupts `angular-typechecker` ->
  `typecheckr` and breaks the build. Replacements MUST be anchored on
  executor-only tokens: `:angular-typecheck` (id suffix, both scoped + unscoped),
  `executors/angular-typecheck` (dir path), the target-key strings
  `"angular-typecheck"` / `"angular-typecheck-spec"`, and run-command tokens
  (`nx ... :angular-typecheck`, `npx nx angular-typecheck`). Verify after: a grep
  for `:angular-typecheck`, `executors/angular-typecheck`, and target-key
  `"angular-typecheck"` returns ZERO in shipped source/config/docs, while the
  `angular-typechecker` (package) occurrence count is UNCHANGED.

### Scope hygiene
- **D-04 (Do not rewrite history / non-referencing docs):** Leave `CHANGELOG.md`
  historical sections and `.planning/` untouched; `AGENTS.md` needs no change. Only
  files that reference the executor id, target name, or implementation directory
  are edited. Prose executor-name mentions in `README.md` are MANDATORY to update
  (SC4: docs); the equivalent prose mention in `CLAUDE.md` (`## Project` section)
  may be updated for accuracy but is low-impact.

### Claude's Discretion
- **D-05 (Human-facing message prefixes -> package name; LOW impact, revisit at
  review):** The diagnostic/log-message prefixes `angular-typecheck: ...` in
  `executor.ts` (4) and `run-typecheck.ts` (1), plus code comments mentioning
  `angular-typecheck`, are human-readable labels, not the executor id.
  Recommendation: change the message prefix to the STABLE package name
  `angular-typechecker:` (unambiguous, never renamed, and clears the last stale
  `angular-typecheck` tokens per SC4); update any spec that asserts the old
  prefix in lockstep. This is easily reversible log text — the planner may instead
  keep it or use `typecheck:`; flag the final choice in the plan.
- **D-06 (Commit as breaking; do NOT cut the release here):** Land the change as a
  single `feat!(...)` (or a `feat` with a `BREAKING CHANGE:` footer) that touches
  `packages/angular-typechecker/` so `nx release` will later compute the 0.1.0
  minor bump (SC5). This phase does NOT run `nx release` / cut a version — the
  0.1.0 cut happens at the milestone Release PR (see AGENTS.md release mechanics).
