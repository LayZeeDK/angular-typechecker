<objective>
Perform the live first npm publish of `angular-typechecker@0.0.1` and stand up tokenless OIDC for every future release. This plan is a HUMAN RUNBOOK, not auto-executed work -- it is the only irreversible action in the phase and it requires out-of-band actions on npmjs.com that no agent can perform (B-01).

Purpose: npm cannot do a package's FIRST publish via OIDC (npm/cli#8544 still OPEN) and the Trusted-Publisher registration is a manual npmjs.com action. The token-seed-then-OIDC bootstrap (D-12) is the safest path: seed the real 0.0.1 from the hardened CI with a short-lived granular write token (still gets provenance because CI has id-token:write), immediately attach the Trusted Publisher, then revoke the token so no standing secret remains.

Output: A live, provenance-attested `angular-typechecker@0.0.1` on npm and a configured Trusted Publisher; no files in this repo change.

GATE: The `--chain`/`auto_advance` MUST treat reaching publish-ready (05-01..05-04 green + the dry-run reviewed) as PHASE SUCCESS and STOP before this plan. Do NOT auto-run any real publish (B-01).

<threat_model>

## Trust Boundaries

| Boundary                                      | Description                                                                                                                                 |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| short-lived seed token -> npm registry        | A long-lived or un-revoked write token is a standing leak vector; it must be granular, short-lived, and revoked immediately after the seed. |
| GitHub OIDC identity -> npm Trusted Publisher | The Trusted Publisher must trust the EXACT workflow + environment, not the whole repo (TanStack vector).                                    |
| published version immutability                | A first publish is irreversible (immutable versions, 72h unpublish window, the name is claimed forever) -- hence human-gated.               |

## STRIDE Threat Register

| Threat ID | Category               | Component                     | Disposition | Mitigation Plan                                                                                                                                                                 |
| --------- | ---------------------- | ----------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-05-17   | Information Disclosure | seed npm token                | mitigate    | Short-lived granular write token scoped to `angular-typechecker` only; revoked immediately after the seed publish (D-12).                                                       |
| T-05-18   | Spoofing / Tampering   | Trusted Publisher trust scope | mitigate    | Register the TP against the exact workflow filename + environment + tick `npm publish`; whole-repo trust avoided (D-12/D-15).                                                   |
| T-05-19   | Repudiation            | unverifiable build origin     | mitigate    | Provenance on the seed (CI id-token:write + NPM_CONFIG_PROVENANCE) and steady-state OIDC; verified via `npm view --json` (D-16).                                                |
| T-05-20   | Elevation of Privilege | unauthorized publish          | mitigate    | Required-reviewer environment approval gates the publish job (D-15); npm 2FA on the account (D-16).                                                                             |
| T-05-SC   | Tampering              | the npm publish action itself | mitigate    | The publish runs the just-audited tarball (05-02 no-install-scripts + leak gates) through the hardened SHA-pinned workflow (05-04); irreversible step is human-approved (B-01). |

</threat_model>
