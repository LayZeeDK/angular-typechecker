## Warnings

### WR-01: AGENTS.md gotcha #3 LANDMINE describes the wrong nx failure mode (hard-error, not silent push)

**File:** `AGENTS.md:136-143`

**Issue:** The LANDMINE block claims that re-enabling
`changelog.workspaceChangelog.createRelease: "github"` while keeping `release.git.push: false`
would cause nx to "**silently push** the version commit + tag during the local `nx release`
step -- BEFORE you curate the changelog -- even with `--skip-publish`." That is factually wrong
for the repo's CURRENT config and inverts the actual nx 23.0.1 behavior.

Verified against `node_modules/nx/dist/src/command-line/release/config/config.js`:

- Lines 136-149: when `git.push` is **explicitly** `false` (`isGitPushExplicitlyDisabled`,
  covering `git.push`, `changelog.git.push`, or `version.git.push`) AND `createRelease` is
  enabled (`isCreateReleaseEnabledAtTheRoot`), nx returns the error code
  `GIT_PUSH_FALSE_WITH_CREATE_RELEASE`.
- Lines 899-913: that error path calls
  `output.error({ title: "The createRelease option for changelogs cannot be enabled when git
  push is explicitly disabled because the commit needs to be pushed to the remote in order to
  tie the release to it" })` and then `process.exit(1)`.

So with the repo's existing `release.git.push: false`, adding `createRelease: "github"`
**HARD-ERRORS at config-load time and never pushes anything** -- the release will not cut at
all. The doc presents the exact opposite (a silent, dangerous push).

The genuine silent-push hazard is a DIFFERENT scenario: when `git.push` is left at its
DEFAULT (`gitDefaults.push = false`, config.js:118) -- i.e. NOT explicitly written -- and
`createRelease` is enabled, nx flips `changelogGitDefaults.push` to `true`
(config.js:150-160) so `nx release` pushes the tag. `--skip-publish` does NOT suppress that
push: the push is gated by `changelog.git.push` (changelog.js:566,
`if (args.gitPush ?? nxReleaseConfig.changelog.git.push)`), independent of `skipPublish`. The
doc conflates these two cases under one "silent push" claim.

This matters because the file's own "Changing this file" policy (`AGENTS.md:6-17`) demands
factual accuracy against the installed tooling, and the cited precedent (a release-mechanics
claim "once wrong about the 0.x semver bump shift and about `--skip-publish` semantics") is
exactly this class of defect. The protective conclusion -- `release.git.push: false` +
`createRelease: false` is safe, and curation must precede the push -- is correct; only the
mechanism narrative is wrong.

**Fix:** Replace the LANDMINE paragraph with a two-case, source-accurate version:

```markdown
   **LANDMINE -- do NOT re-enable `changelog.workspaceChangelog.createRelease: "github"`.**
   nx 23 requires `git push` whenever `createRelease` is set (it must push the tag to tie the
   GitHub Release to it). How that manifests depends on the current `git.push` value -- and
   BOTH outcomes defeat the curate-before-push flow:

   - **With the repo's current explicit `release.git.push: false`:** nx HARD-ERRORS at
     config-load time with `GIT_PUSH_FALSE_WITH_CREATE_RELEASE` ("The createRelease option for
     changelogs cannot be enabled when git push is explicitly disabled ...") and
     `process.exit(1)` -- verified in nx 23.0.1 `command-line/release/config/config.js` (error
     raised ~136-149, reported + exit ~899-913). Every `nx release` invocation then fails until
     you revert one of the two settings; nothing is pushed.
   - **If you ALSO drop the explicit `git.push: false`:** nx defaults the changelog git `push`
     to `true` whenever `createRelease` is set (config.js:150-160), so `nx release` pushes the
     version commit + tag during the LOCAL step -- BEFORE you curate the changelog.
     `--skip-publish` does NOT suppress this: it only answers "no" to the npm-publish prompt;
     the git push is gated by `changelog.git.push` (changelog.js:566), not by `skipPublish`.
     This is the real silent-push hazard that once pushed an un-curated commit + tag to a
     force-push-protected `main`, which could not be cleanly undone.

   `release.git.push: false` + `createRelease: false` is the fix for both: the local cut stays
   push-free, and curation always precedes the manual `git push origin
   angular-typechecker@<version>`.
```

### IN-02: gotcha #3 / checklist understate that the CI publish PAUSES on the environment approval

**File:** `AGENTS.md:124-134, 153-156`

**Issue:** Gotcha #3 (and the quick checklist) list "push the tag ... approve the `npm-publish`
environment" as one step. This is correct but a reader could push the tag and walk away
expecting an automatic publish. Per `release.yml:39-43`, the `npm-publish` environment has a
Required Reviewer; the tag push only QUEUES the publish job, which then BLOCKS on that approval
before it runs `nx release publish`. Making the pause explicit avoids a "tag pushed but nothing
published" surprise.

**Fix:** In step (3), change "approve the `npm-publish` environment" to something like "-- the
publish job then PAUSES on the `npm-publish` environment's Required Reviewer until you approve
it; only then does the OIDC publish run." This mirrors the load-bearing comment at
`release.yml:39-42`.
