The **CI-authoritative** proof of the same shipped-bin exit-code contract is **VER-04** --
the automated `angular-typechecker-cli-e2e` project shipped in Plans 28-01/02/03. It
installs the packed tarball from Verdaccio and runs the shipped `.bin` shim

workspace) + pnpm, on Linux AND Windows (Node 24), asserting the literal OS exit codes
`0`/`1`/`2` through the PM-generated shim. VER-05 is the human-run confidence gate ON TOP
of VER-04, against REAL on-stack OSS workspaces of BOTH kinds (Angular CLI and Nx).

### Shipped-bin contract (FROZEN -- Phases 25-27; this gate only OBSERVES it)

- Input flag is `-c` / `--tsConfig` (repeatable, REQUIRED). Every invocation below uses
  `-c` / `--tsConfig`. `-p` / `--project` is deliberately UNREGISTERED and surfaces as an
  unknown-flag usage error (exit `2`) -- there is exactly ONE `-p` cell per clone, marked
  as a valid usage-error test.
- Exit codes: `0` clean / `1` verdict-fail / `2` infrastructure-or-usage. (Verbatim from
  the shipped `HELP_TEXT`.)
- Both bin names (`angular-typechecker`, `atc`) resolve to the SAME shipped file
  (`node_modules/angular-typechecker/src/cli/bin.js`); the shims are
  `node_modules/.bin/{angular-typechecker,atc}` (POSIX) / `.cmd` + `.ps1` (Windows).
- The safe uninstalled invocation is `npx angular-typechecker`. **NEVER run `atc` through
  `npx`** -- `atc@0.0.6` is an unrelated published npm package (a supply-chain hazard).
  Use the installed `.bin/atc` shim BY PATH, or `npx angular-typechecker`, only.

### How to install the shipped bin into each clone

The v0.2.1 npm release does NOT ship the standalone CLI (the `bin` landed in Phase 27,
unreleased). So install the LOCAL packed tarball -- the EXACT artifact `nx release publish`
would ship -- NOT `npm i angular-typechecker` (which would fetch the CLI-less published
version). Test 1 builds + packs it once and exports `$ABS_TGZ`.

Install into each clone with the clone's OWN package manager (VER-05 proves the bin at
real tsconfigs; the PM x shim matrix is VER-04's job):

- npm clone: `npm install -D "$ABS_TGZ"`
- pnpm-workspace clone (realworld-angular): `pnpm add -w -D "$ABS_TGZ"` (root install;
  a bare `pnpm add` errors `ERR_PNPM_ADDING_TO_ROOT` in a workspace -- see ACV-01).
- yarn clone: `yarn add -D "$ABS_TGZ"`

The installed CLI reaches `@angular/compiler-cli` + `typescript` via the CLONE's own
`node_modules` (`await import(...)`), so run `<pm> install` FIRST (on-stack -> no
`--legacy-peer-deps`) before installing the tarball.

### Assertion shape per clone (mirrors ACV-01, adapted to the standalone bin)

- **RED:** plant a DISTINCT diagnostic CODE per leaf (TS2322 component / TS2345 spec /
  TS2554 lib -- the ACV-01 codes) via a source edit; `atc -c <leaf>` exits `1` and stdout
  contains the planted `TSxxxx`; stdout has NO `ERR_REQUIRE_ESM` and NO "infrastructure
  error" (the non-zero exit is a REAL diagnostic, not a broken ESM bridge / missing peer).
  Revert the plant (`git checkout -- <file>`) -> back to GREEN.
- **GREEN:** clean tree; `atc -c <tsconfig>` exits `0`.
- **BAD-PATH:** `atc -c does-not-exist.json` exits `2` (infrastructure); plus the usage
  cells `atc` (no `-c`) -> `2`, `atc --nonsense` -> `2`, and `atc -p <tsconfig>` -> `2`
  (the ONE `-p` cell: `-p` is unregistered, so it is itself a valid usage error).

**Windows / MSYS note (manual runs only):** on Git Bash use `/d/...` style paths, NOT
`D:/...` -- Git Bash mis-parses the `D:` drive letter as a remote host. Run the
extensionless shim as `./node_modules/.bin/atc` from the clone root.
