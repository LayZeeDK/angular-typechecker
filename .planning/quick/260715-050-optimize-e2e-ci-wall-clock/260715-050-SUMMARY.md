# Quick Task 260715-050: Optimize e2e-tier CI wall-clock -- SUMMARY

**Outcome: SHIPPED Lever A -- the e2e tier is split into a per-project matrix, cutting the CI
wall-clock from 620s to ~366s (~41% faster), fully green on the whole `ci` gate.** Lever B (a per-cell
Verdaccio uplink cache) was implemented + measured on a throwaway PR and DISCARDED as within CI noise.
A GitHub-backed Nx remote cache was researched, found feasible + CREEP-mitigable, and DEFERRED to its
own phase (ROADMAP Phase 25) per the user.

## What shipped (on the feature branch, commit c7eabb4)

- **`.github/workflows/ci.yml`** -- the single serialized `e2e` job (`nx run-many -t e2e --parallel=2`)
  is replaced by:
  - a lean **`discover`** job: `node tools/ci/list-e2e-projects.mjs` -> `outputs.projects` (a pure
    fs-read of `e2e/*/project.json`, no `npm ci`/build), feeding
  - a **per-project `e2e` matrix**: `fromJSON(needs.discover.outputs.projects || '[...fallback...]')`,
    one runner per e2e project, `nx run-many -t {typecheck,e2e} -p ${{ matrix.project }}`. The four e2e
    projects now run on SEPARATE runners in parallel instead of serially on one.
  - `discover` added to the `ci` aggregate `needs` (the existing `contains(needs.*.result,...)` gate
    catches a discover/cell failure).
- **`tools/ci/list-e2e-projects.mjs`** (new) -- the dynamic discovery script (auto-covers any future
  e2e project; no static list to drift).
- **`packages/angular-typechecker/src/ci-e2e-coverage-guard.spec.ts`** -- GUARD-01/01b/01d updated for
  the dynamic-matrix wiring; a NEW GUARD-01b check runs the discovery CLI and asserts its output equals
  GUARD-01's `enumerateE2eProjects()` (the matrix cannot silently drift from the real e2e projects).
- **`.fallowrc.jsonc`** -- `tools/ci/list-e2e-projects.mjs` declared as a fallow `entry` (a node-invoked
  script is unreachable via the import graph).

Design preserved intact: each cell rebuilds the small `@nx/js:tsc` plugin (~2-4s) via the UNTOUCHED
`e2e`-target `dependsOn: angular-typechecker:build`, so local dev + GUARD-01e are unchanged. install-e2e
+ cache-e2e keep `parallelism:false` for the LOCAL full-tier run. `release.yml` unchanged.

## Measurements (real CI, throwaway draft PR #36)

- **Baseline:** single `e2e` job = **620s** (from the green PR #35 run; per-spec breakdown in
  MEASUREMENTS.md).
- **Lever A (split):** tier wall (discover start -> last cell finish) = **~366s (~41% faster)**. Floor =
  the ng-cli-e2e cell (~356s), dominated by its serial ng-add-{yarn,pnpm,npm} installs (the irreducible
  per-project-split floor).
- **Lever B (per-cell Verdaccio cache):** miss vs hit on the two install-heavy cells: install-e2e
  249s->260s (+11s, SLOWER), ng-cli-e2e 336s->307s (-29s). OPPOSITE signs => within CI noise =>
  **DISCARDED** (the CPU-bound typecheck + install-compute floor swamps the uplink-fetch savings, as the
  nub research predicted).

## Key findings

- **A cross-runner build-artifact handoff is a no-op in nx.** The first design uploaded `dist` +
  `.nx/cache` for the cells to reuse; CI proved nx REJECTS a foreign `.nx/cache` (`unknown-local-cache`)
  and rebuilds per cell via `dependsOn` anyway. Dropped the artifact + build job for the lean discover
  job. (The supported cross-runner path is a real Nx REMOTE cache -> Phase 25.)
- **Release provenance is already covered at zero cost:** the `install-e2e` cell builds+publishes+installs
  the exact `dist/packages/angular-typechecker` packageRoot `release.yml` ships, and it runs on the
  Release-PR (a PR -> `ci.yml` e2e) BEFORE the tag push.
- **The ~41% win is entirely parallelism**, not build-sharing or fetch-caching -- both of those proved
  marginal/inert here.
