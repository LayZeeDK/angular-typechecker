<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted PR -> CI workflow | `pull_request` runs untrusted contributor code with READ-ONLY default permissions; no PR field is interpolated into a `run:` step |
| GitHub Actions marketplace -> workflow | Third-party actions are pinned to full 40-char commit SHAs (a mutable tag repoint was the tj-actions vector) |
| checkout credential -> .git/config | `persist-credentials: false` prevents a checkout token persisting to disk for exfil |
| packed tarball (e2e job) -> CI runner | The e2e job installs THIS repo's own freshly-packed tarball (no third-party registry fetch; Phase-5 audit already asserts no install scripts) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05 | Elevation / Tampering | the trigger event | mitigate | Trigger on `pull_request` + `push` to `main`, NEVER `pull_request_target`; top-level `permissions: { contents: read }`; no job re-grants write (the s1ngularity command-injection + token-leak vector) |
| T-06-06 | Tampering | third-party GitHub Actions | mitigate | Every action is a full 40-char SHA pin (checkout@93cb6e... v5.0.1, setup-node@a0853c... v5.0.0, pnpm/action-setup@008330... v6.0.9) with Dependabot github-actions lockstep -- the tj-actions mutable-tag repoint vector |
